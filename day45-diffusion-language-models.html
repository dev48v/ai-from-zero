AIFromZero · Day 45

🌫️ Diffusion Language Models — writing text by clearing the fog, not typing left-to-right. A normal LLM is autoregressive: it writes one token at a time, strictly left-to-right, and once a token is out it's frozen — it can't unsee a bad word. A diffusion LM (LLaDA, Mercury) starts from a whole sentence of [MASK] and denoises it: at each step it predicts every blank at once, keeps only the most-confident ones, and repeats — so it fills many tokens in parallel, in any order, and can even go back and revise an early guess as context arrives. Fewer steps than there are tokens, and a chance to fix mistakes the left-to-right writer never gets.

Start from a sentence of pure [MASK] — then denoise it into words, most-confident-first

Every slot below begins as [MASK]. Each denoise step scores all the blanks at once — the indigo meter under each mask is how confident the model is about that slot right now — and reveals the top few. Easy, predictable words (the anchors) light up first; their neighbours then gain context and become confident too, so the sentence fills outward in any order, several tokens per step. With refinement on, a word guessed early with little context appears amber (a tentative guess) and later flips green when context corrects it — the revision a left-to-right writer can never make. Every number here is a real confidence schedule computed live in your browser, not a canned animation.

🔎 Why parallel wins on steps — and any-order wins on quality. An N-token sentence takes the autoregressive writer N steps, always. The diffusion writer needs about ⌈N/K⌉ steps, because it commits several tokens at once — and it commits the easy, confident ones first, then lets their context resolve the hard ones (instead of being forced to guess left-to-right before the right-hand context exists). Because nothing is frozen until the model chooses, it can also re-mask and rewrite a slot it now thinks is wrong. The catch: predicting every position each step is more compute per step, and it can't reuse a KV-cache the way a left-to-right decoder does — so real systems (LLaDA, Mercury) trade a bit of that for lower latency and the freedom to self-correct.

Diffusion language models generate text the way image diffusion generates pictures: begin with pure noise — here a sentence of [MASK] — and denoise it over a handful of steps. Each step predicts every blank at once and keeps only the most-confident tokens, so words appear in parallel and in any order, easy anchors first, hard tokens once their context exists. Unlike an autoregressive model — which writes strictly left-to-right and freezes each token forever — a diffusion LM can revise an early guess, and finishes in fewer steps than there are tokens. It's a genuinely different bet from both the transformer default and from Mamba (Day 43): Mamba keeps the left-to-right order but makes it linear-time; diffusion drops the left-to-right order entirely. The price is more compute per step and no free KV-cache — which is why autoregressive still dominates, while text-diffusion (LLaDA, Mercury) is the fast-moving challenger to watch.

🔨 Build a diffusion language model from scratch

    
Reproduce the whole LOOK demo: a target sentence, a per-token confidence signal, the most-confident-first unmask schedule that fills many tokens per step in any order, the refinement pass that revises early guesses, and the left-to-right autoregressive baseline it races against. This is the exact engine powering LOOK ① and ②.

    
    
      
  1. 
        
    1
    The sentence — each token has a "how predictable" prior
    
        
    In a real model a transformer scores every slot; here we stand in for it with a small, honest signal. Function words (the, in, at) are highly predictable → high prior; content words (diffusion, masked) are hard on their own → low prior. Each hard word also carries a plausible wrong guess (its distractor) for when it's forced to commit with no context.
    
        
    // the target sentence + a per-token "prior" (0..1 = how predictable alone)
const TOKENS = [
  { w:"a",         prior:0.90, dist:null      },  // function words: easy anchors
  { w:"diffusion", prior:0.34, dist:"language" },  // content words: hard alone
  { w:"model",     prior:0.60, dist:"system"   },
  { w:"fills",     prior:0.44, dist:"writes"   },
  { w:"in",        prior:0.90, dist:null       },
  { w:"all",       prior:0.70, dist:"some"     },
  { w:"the",       prior:0.92, dist:null       },
  { w:"masked",    prior:0.40, dist:"hidden"   },
  { w:"words",     prior:0.55, dist:"tokens"   },
  { w:"at",        prior:0.88, dist:null       },
  { w:"once",      prior:0.66, dist:"speed"    },
];
const N = TOKENS.length;              // 11 slots
    
      
    2. 
      
  2. 
        
    2
    The starting point — a sentence of pure [MASK]
    
        
    Autoregressive generation starts empty and appends. Diffusion generation starts full — every position exists, but every one is noise (a [MASK] token). Generation is the process of turning that all-masked sequence into clean tokens. This is the text version of "start from a noisy image."
    
        
    // every slot starts masked — the "pure noise" the model will denoise
let seq = TOKENS.map(() => ({ revealed:false, word:"[MASK]", kind:"mask" }));
// seeded noise so a run is reproducible but the schedule is genuinely emergent
const noise = TOKENS.map((_,i) => (rand()*0.12 - 0.06));   // tiny ±0.06 jitter
    
      
    3. 
      
  3. 
        
    3
    Confidence — prior plus context from revealed neighbours
    
        
    The key signal. A slot's confidence is its own predictability plus a bonus for every already-revealed neighbour. That's what makes generation spread: an isolated content word is unsure, but once the words around it are known, its meaning is pinned down and confidence jumps. Real diffusion LMs read this off the model's own token probabilities each step.
    
        
    function revealedNeighbours(seq, i){
  let n = 0;
  if (i > 0     && seq[i-1].revealed) n++;
  if (i < N-1   && seq[i+1].revealed) n++;
  return n;                                   // 0, 1 or 2
}
function confidence(seq, i){
  return TOKENS[i].prior                       // predictable on its own?
       + 0.26 * revealedNeighbours(seq, i)     // + context as neighbours land
       + noise[i];                             // + a touch of jitter
}
const THRESH = 0.72;   // above this, the model is sure enough to commit cleanly
    
      
    4. 
      
  4. 
        
    4
    The schedule — unmask the top-K most confident, every step
    
        
    Here is the whole trick. Each step, score all the masked slots, sort by confidence, and reveal the best K of them at once — multiple tokens, in confidence order, not left-to-right. Bigger K = more parallel = fewer steps. The anchors go first; each reveal raises its neighbours' confidence, so the next step's winners are usually right next door.
    
        
    function denoiseStep(seq, K){
  const masked = [];
  for (let i=0;i<N;i++) if (!seq[i].revealed) masked.push(i);
  masked.sort((a,b) => confidence(seq,b) - confidence(seq,a));  // most-confident first
  for (const i of masked.slice(0, K)){        // reveal K at once, any order
    const sure = confidence(seq,i) >= THRESH;
    seq[i] = sure || !TOKENS[i].dist
      ? { revealed:true, word:TOKENS[i].w,   kind:"confident" }  // commit clean
      : { revealed:true, word:TOKENS[i].dist, kind:"tentative", i }; // a guess (step 5 fixes it)
  }
}
// steps to finish ≈ ceil(N / K)   — fewer than N, the autoregressive count
    
      
    5. 
      
  5. 
        
    5
    Refinement — revise a guess once context arrives
    
        
    A slot revealed early, before its neighbours existed, is only a tentative guess (amber). Diffusion's superpower: it isn't frozen. Each step, before unmasking, re-check every tentative slot — now that context has landed, its confidence has climbed past the threshold, so overwrite the guess with the correct word (green). This is the correction an autoregressive model structurally cannot make.
    
        
    function refine(seq){                    // run at the START of each step
  for (let i=0;i<N;i++){
    if (seq[i].kind === "tentative" && confidence(seq,i) >= THRESH){
      seq[i] = { revealed:true, word:TOKENS[i].w, kind:"revised" };  // fix it
    }
  }
}
// early guess "language"  --(neighbours 'a','model' land)-->  "diffusion"
// nothing is ever locked until the model itself is confident.
    
      
    6. 
      
  6. 
        
    6
    The baseline — autoregressive, one token, left-to-right, frozen
    
        
    The model to beat. It reveals slot 0, then 1, then 2 — one per step, in order — and each token, once written, only ever saw what was to its left and can never change. That's N steps and no second chances. Put the two side by side and the trade-off is the whole story: left-to-right is simple and cache-friendly; diffusion is parallel, any-order, and revisable.
    
        
    function autoregressiveStep(seq, cursor){
  seq[cursor] = { revealed:true, word:TOKENS[cursor].w, kind:"frozen" }; // 🔒 forever
  return cursor + 1;                    // strictly left-to-right, one at a time
}
// diffusion : ceil(11 / K) steps, any order, can revise   (LLaDA, Mercury)
// autoregr. : 11 steps, fixed order, frozen                (GPT-style default)
// Mamba (Day 43): still left-to-right, but linear-time instead of n^2.
// diffusion's bet is different again: drop the left-to-right order entirely.
