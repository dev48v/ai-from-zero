AIFromZero · Day 59

🧬 Model Merging — two fine-tunes, one model, zero GPUs. A trained checkpoint is nothing but a long list of numbers, so two models fine-tuned from the same base sit at two points in the same weight space — and you can do arithmetic on them. Subtract the base from a fine-tune and you get a task vector τ = θ_finetuned − θ_base: the direction that encodes the skill it learned. Add two task vectors back onto the base and you get one model that can do both jobs, without a single training step, without the original data, without touching a GPU — this is task arithmetic. Flip the sign and you unlearn a skill instead. The catch is interference: the two skills fight over shared parameters, and where they want opposite signs, naive averaging cancels both to nearly zero. TIES fixes that by Trimming the tiny values, Electing a single sign per parameter, and averaging only the entries that agree; DARE randomly drops and rescales; SLERP interpolates on the sphere so the weight norm doesn't shrink. Below, two real classifiers are actually trained in your browser by gradient descent from one shared base — a review-sentiment model and a spam filter — then merged live by any of those five methods, with real held-out accuracy on both tasks recomputed on every slider move. No API, no library, all deterministic.

Two specialists in, one generalist out.

On load, three logistic-regression models are trained for real, right here: a shared base (pre-trained on a generic politeness task), then two fine-tunes from it — Model A (review sentiment) and Model B (spam filter). Neither can do the other's job. Pick a merge method, move the sliders, and the merged weights are recomputed and re-scored on both held-out sets, live. Every number below comes from real gradient descent and a real accuracy count — nothing is hard-coded.

What's happening
The merged model, judging real held-out examples — three from each task, scored by the current merge.

Model merging turns "which fine-tune do I ship?" into "ship all of them". Because a checkpoint is a vector, a learned skill is a direction — τ = θ_finetuned − θ_base — and directions add, scale and negate. Averaging is the crude version; task arithmetic gives you a dial per skill; TIES handles the sign fights that averaging silently cancels; DARE sparsifies before merging; SLERP keeps the weight norm intact. It costs minutes of CPU instead of GPU-days, needs no training data, and is how a huge share of the open-weight models on Hugging Face are actually made — mergekit is the standard tool. The one rule nobody escapes: merging is a hypothesis, the eval is the answer.

    Load three checkpoints that share an ancestor
    
        
    Merging is parameter-wise, so the models must have identical shapes: same architecture, same layer names, same tokenizer, and — for the arithmetic to mean anything — the same pre-trained base. Two fine-tunes of the same base are mergeable; a Llama and a Mistral are not.
    
        
    import torch
from safetensors.torch import load_file

base = load_file("base/model.safetensors")      # the shared pre-trained checkpoint
ft_a = load_file("sentiment/model.safetensors") # fine-tune 1
ft_b = load_file("spam/model.safetensors")      # fine-tune 2

assert base.keys() == ft_a.keys() == ft_b.keys()          # same parameter names
assert all(base[k].shape == ft_a[k].shape for k in base)  # same shapes

    Task vectors — the skill as a direction
    
        
    Subtract the base from a fine-tune and what's left is only what fine-tuning changed: τ = θ_ft − θ_base. That difference vector is the skill. Note it is mostly near-zero — fine-tuning nudges a small fraction of the parameters, which is exactly why two task vectors can coexist.
    
        
    def task_vector(ft, base):
    return {k: ft[k].float() - base[k].float() for k in base}

tau_a = task_vector(ft_a, base)     # "review sentiment"
tau_b = task_vector(ft_b, base)     # "spam filtering"

# sanity: base + tau_a reconstructs the fine-tune exactly
assert all(torch.allclose(base[k] + tau_a[k], ft_a[k].float()) for k in base)

    Model soup — the one-line merge
    
        
    The simplest merge is a plain (optionally weighted) average of the fine-tunes. It's identical to adding both task vectors at λ = 0.5 each, which is a useful way to see it: a soup is just task arithmetic with the weights forced to sum to 1.
    
        
    def soup(models, weights=None):
    n = len(models)
    w = weights or [1 / n] * n
    return {k: sum(wi * m[k].float() for wi, m in zip(w, models))
            for k in models[0]}

merged = soup([ft_a, ft_b])                      # equal soup
# identical to: base + 0.5*tau_a + 0.5*tau_b

    Task arithmetic — a dial per skill, and negation
    
        
    Give each task vector its own coefficient and you get a mixing desk. Positive λ adds the skill, λ = 0 returns the base, and a negative λ subtracts it — the model gets measurably worse at that task while the others are untouched. That is the cheapest known form of unlearning.
    
        
    def task_arithmetic(base, taus, lambdas):
    out = {}
    for k in base:
        v = base[k].float().clone()
        for tau, lam in zip(taus, lambdas):
            v += lam * tau[k]
        out[k] = v
    return out

both   = task_arithmetic(base, [tau_a, tau_b], [0.5, 0.5])   # do both jobs
forget = task_arithmetic(base, [tau_a],        [-1.0])       # unlearn sentiment
# lambda is the single most important knob - sweep it against your eval

    Measure the interference before you fix it
    
        
    Two failure modes wreck naive merges. Redundancy: most entries of a task vector are noise-sized and only dilute the useful ones. Sign conflict: where the two skills disagree, averaging drives the parameter toward zero and both skills lose it. Count the damage first — it tells you whether TIES will help.
    
        
    import torch

def interference(tau_a, tau_b, eps=0.05):
    conflicts = kept = 0
    for k in tau_a:
        a, b = tau_a[k], tau_b[k]
        big = (a.abs() > eps) & (b.abs() > eps)
        conflicts += (big & (a.sign() != b.sign())).sum().item()
        kept      += big.sum().item()
    return conflicts, kept

c, n = interference(tau_a, tau_b)
print(f"{c}/{n} shared parameters disagree on sign")   # these cancel in a soup

    TIES — Trim, Elect sign, Disjoint Merge
    
        
    TIES (NeurIPS 2023) fixes both problems in three passes. Trim: keep only the top-k% of each task vector by magnitude, zero the rest — the noise is gone. Elect: for each parameter, pick the sign with the larger total magnitude across models. Disjoint merge: average only the models that agree with the elected sign, so the losers don't drag it back to zero.
    
        
    def ties(base, taus, k=0.2, lam=1.0):
    out = {}
    for key in base:
        stack = torch.stack([t[key].flatten() for t in taus])     # [n_models, P]

        # 1. TRIM - keep top-k% by |value| within each model
        n_keep = max(1, int(k * stack.shape[1]))
        thresh = stack.abs().kthvalue(stack.shape[1] - n_keep + 1, dim=1,
                                      keepdim=True).values
        stack = stack * (stack.abs() >= thresh)

        # 2. ELECT - one sign per parameter, by total magnitude
        elected = stack.sum(dim=0).sign()

        # 3. DISJOINT MERGE - mean over the entries that agree
        agree = (stack.sign() == elected) & (stack != 0)
        merged = (stack * agree).sum(0) / agree.sum(0).clamp(min=1)

        out[key] = base[key].float() + lam * merged.view(base[key].shape)
    return out

    DARE — Drop And REscale
    
        
    DARE throws away a random fraction p of each task vector's entries and multiplies the survivors by 1/(1−p), so the expected vector is unchanged. Because task vectors are so redundant, you can drop 90% and lose almost nothing — while the sparser vectors overlap far less, which cuts interference. It composes with TIES (dare_ties in mergekit).
    
        
    def dare(tau, p=0.9, generator=None):
    out = {}
    for k, v in tau.items():
        mask = torch.rand(v.shape, generator=generator) >= p   # keep with prob 1-p
        out[k] = v * mask / (1 - p)                            # rescale survivors
    return out
# E[dare(tau)] == tau  ->  same direction, a fraction of the entries
merged = task_arithmetic(base, [dare(tau_a), dare(tau_b)], [1.0, 1.0])

    SLERP — interpolate on the sphere, not the line
    
        
    A straight-line average between two weight vectors that point in different directions is shorter than either — the merged model's activations shrink. SLERP walks the arc between them at constant angular speed and interpolates the magnitude separately, so the norm is preserved. It's the default for merging exactly two models.
    
        
    def slerp(a, b, t=0.5, eps=1e-8):
    na, nb = a.norm(), b.norm()
    ua, ub = a / na, b / nb
    omega  = torch.acos((ua * ub).sum().clamp(-1, 1))     # angle between them
    s = torch.sin(omega)
    if s.abs() < eps:                                     # nearly parallel
        return (1 - t) * a + t * b
    direction = (torch.sin((1 - t) * omega) * ua + torch.sin(t * omega) * ub) / s
    return direction * ((1 - t) * na + t * nb)            # magnitude interpolated
# linear average shrinks the norm; SLERP does not

    In practice — mergekit, then evaluate
    
        
    Nobody hand-rolls this at 7B scale. mergekit takes a YAML recipe, streams the tensors so it runs on CPU with modest RAM, and writes a normal checkpoint you can serve anywhere. The merge itself takes minutes — the real work is the sweep: λ and k are hyper-parameters, and only your eval set can tell you which combination actually won.

🎉 Day 59 of AIFromZero done.
Model merging combines several fine-tunes of the same base into one checkpoint by doing arithmetic on their weights — no training, no data, no GPU. Subtract the base to get a task vector τ = θ_ft − θ_base, then add task vectors to gain skills, or negate one to unlearn a skill. Naive averaging suffers interference — redundant entries dilute the signal and sign conflicts cancel it — which is what TIES (trim → elect sign → disjoint merge), DARE (drop & rescale) and SLERP (arc interpolation, norm preserved) each attack from a different angle. mergekit ships all of them, λ and k are the knobs, and the eval set is the only judge. 👉 Tomorrow — Day 60: continuing AIFromZero.
