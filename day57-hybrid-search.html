AIFromZero · Day 57

🔀 Hybrid Search — two engines that fail in opposite ways, fused into one that doesn't. Modern retrieval has two great tools that are each half-blind. Lexical search (BM25) matches the actual words: it is unbeatable on exact keywords, product codes, error IDs and rare technical terms — but it is literal, so it cannot tell that "sign in" and "log in" mean the same thing, and a pure paraphrase with no shared words scores zero. Dense vector search matches meaning: it embeds query and documents into vectors and ranks by cosine, so it sails through paraphrase and synonyms — but it smears rare tokens into a fuzzy semantic average, so it can rank a generic "error" article above the one doc that names your exact error code. Neither is strictly better; they miss different things. Hybrid search runs both and fuses the two ranked lists. The trick is that you don't need the two scores to live on the same scale: Reciprocal Rank Fusion (RRF) throws the scores away and adds up 1/(k+rank) across lists, so a doc that either engine ranked highly floats to the top — a scale-free vote. (A weighted sum of normalized scores is the alternative, and the demo shows why the normalize step is not optional.) Below is a live, fully self-contained engine over a baked-in help-centre corpus — a real BM25 (tf saturation via k1, length-norm via b, proper idf) and a hand-built concept-space cosine standing in for dense embeddings — with a query that BM25 alone half-answers, dense alone half-answers, and hybrid gets fully right. No API, no LLM, all deterministic.

Keywords and meaning — fuse the two rankings.

Nine help-centre articles are the corpus. BM25 (lexical) scores every doc by exact word overlap — great on codes & rare terms, blind to paraphrase. Dense (semantic) scores by meaning in a concept space — great on paraphrase, fuzzy on exact codes. Watch each engine miss something the other catches, then fuse them with RRF (or a weighted sum) and see the truly-relevant docs rise to the top. Everything is deterministic and runs in your browser — no network, no embedding API, no LLM.

Hybrid search wins because its two halves fail independently. BM25 can't see that a paraphrase means the same thing; dense can't hold onto an exact code. Fuse them and each engine covers the other's blind spot — a doc only needs to be strong in one list to survive. RRF makes that fusion trivial: it uses only the ranks, so the two engines never have to agree on a scale, and there's a single knob (k). A weighted sum can outperform it when you carefully normalize and tune α, but that calibration is exactly what RRF lets you skip. This demo uses a toy BM25 and a concept-space stand-in for embeddings, but the shape is the real thing — Weaviate, Elasticsearch/OpenSearch, Qdrant, Milvus and pgvector all ship native BM25+vector hybrid with RRF built in, and it usually feeds a reranker (Day 56) before the LLM ever reads a word.

🔨 Build hybrid search — BM25 + dense, fused with RRF

    
Reproduce the LOOK engine as real code: score the corpus two ways — a lexical BM25 and a dense embedding cosine — then fuse the two ranked lists so a doc strong in either survives. The toy uses a concept-space stand-in for embeddings; the last block swaps in a real embedder plus a native-hybrid vector DB and hands the result to a reranker and Claude. Every block is the exact idea flowing through LOOK.

    The corpus and a two-sided query
    
        
    One query can carry both a paraphrase and an exact code. BM25 will nail the code and whiff the paraphrase; dense will do the reverse. That split is the whole reason to fuse.
    
        
    corpus = [
    "Trouble logging in? Recover your account access from the log in page...",  # login answer (paraphrase target)
    "Error X0-2231 keeps popping up when a saved session has timed out...",      # the exact-code answer
    "A red error message keeps popping up on the dashboard...",                  # lexical decoy
    "Two factor authentication sends a one time login code to your phone...",    # semantic decoy
    # ...more help-centre articles...
]
query = "I can't sign in and X0-2231 keeps popping up"
#         ^ paraphrase of 'log in'        ^ exact error code

    Lexical engine — BM25 (idf · tf saturation · length-norm)
    
        
    BM25 sums, over each query term in the doc: an idf (rare terms count more), a tf that saturates via k1 (the 5th "password" barely beats the 4th), and a length penalty via b (long docs don't win just by being long). A rare code like X0-2231 gets a huge idf, so the one doc that contains it rockets to the top.
    
        
    import math
N = len(corpus); avgdl = sum(len(d) for d in docs_tok)/N

def idf(t):                                   # BM25 idf, non-negative
    n = sum(t in set(d) for d in docs_tok)
    return math.log(1 + (N - n + 0.5)/(n + 0.5))

def bm25(q_tok, d, k1=1.5, b=0.75):
    score, dl = 0.0, len(d)
    for t in set(q_tok):
        f = d.count(t)
        if not f: continue
        score += idf(t) * (f*(k1+1)) / (f + k1*(1 - b + b*dl/avgdl))
    return score
lex = sorted(range(N), key=lambda i: bm25(q_tok, docs_tok[i]), reverse=True)

    Semantic engine — dense embeddings + cosine
    
        
    A dense embedder maps text to a vector where meaning, not spelling, decides closeness — so "sign in" lands next to "log in". Rank by cosine. The LOOK demo fakes the embedder by mapping words to shared concept buckets; production uses a real model, but the ranking step is identical.
    
        
    from sentence_transformers import SentenceTransformer, util

embed   = SentenceTransformer("all-MiniLM-L6-v2")
doc_emb = embed.encode(corpus, convert_to_tensor=True)   # precomputed offline
q_emb   = embed.encode(query,  convert_to_tensor=True)

sims = util.cos_sim(q_emb, doc_emb)[0]
dense = sims.argsort(descending=True).tolist()   # by meaning, not words
# 'sign in' ~ 'log in' -> the paraphrase answer ranks high;
# but the exact code X0-2231 blurs into a generic 'error' vector.

    Fuse with Reciprocal Rank Fusion (RRF)
    
        
    RRF ignores the scores entirely — they live on incompatible scales — and adds 1/(k+rank) across every list a doc appears in. A doc ranked #1 anywhere gets a big vote; being decent in both lists also adds up. A doc a list never retrieved simply contributes 0 from that list.
    
        
    def rrf(rankings, k=60):
    score = {}
    for ranked in rankings:                 # e.g. [lex, dense]
        for rank, doc in enumerate(ranked, start=1):
            score[doc] = score.get(doc, 0) + 1.0/(k + rank)
    return sorted(score, key=score.get, reverse=True)

fused = rrf([lex, dense], k=60)
# the code doc (BM25 #1) and the login doc (dense #1) BOTH surface -
# each was #1 in one list, so each earns a top 1/(k+1) vote.

    The alternative — weighted sum (and why you must normalize)
    
        
    You can fuse the scores directly with α·BM25 + (1−α)·dense — but BM25 is unbounded (0–tens) while cosine is 0–1, so without a min-max normalize BM25 dominates no matter what α you pick. Normalize each list to 0–1 first, then α is a real dial. RRF sidesteps this entire calibration by using ranks.
    
        
    def minmax(scores):
    lo, hi = min(scores.values()), max(scores.values())
    return {d: (s-lo)/(hi-lo) if hi>lo else 0.0 for d, s in scores.items()}

def weighted(lex_s, dense_s, alpha=0.5, normalize=True):
    L = minmax(lex_s)   if normalize else lex_s
    D = minmax(dense_s) if normalize else dense_s
    keys = set(L) | set(D)
    return sorted(keys, key=lambda d: alpha*L.get(d,0) + (1-alpha)*D.get(d,0), reverse=True)
# normalize=False -> BM25's raw magnitude bulldozes cosine. RRF has no such trap.

    Hybrid search in one function
    
        
    Wrap it: score lexically, score densely, fuse, cut to top-k. Each retriever usually returns its own top-N first (so RRF fuses shortlists, not the whole corpus). This retrieve-both-then-fuse shape is the entire pattern.
    
        
    def hybrid_search(query, k=10, rrf_k=60):
    q_tok = tokenize(query)
    lex   = sorted(range(N), key=lambda i: bm25(q_tok, docs_tok[i]), reverse=True)[:50]
    lex   = [i for i in lex if bm25(q_tok, docs_tok[i]) > 0]   # only real matches vote
    q_emb = embed.encode(query, convert_to_tensor=True)
    dense = util.cos_sim(q_emb, doc_emb)[0].argsort(descending=True).tolist()[:50]
    return rrf([lex, dense], k=rrf_k)[:k]      # fused top-k
# keyword precision + semantic recall, in one ranked list

    In practice — native hybrid, then rerank, then Claude
    
        
    You rarely hand-roll this. Weaviate, Elasticsearch/OpenSearch, Qdrant, Milvus, pgvector all expose BM25+vector hybrid with RRF as a single query. Then feed the fused shortlist to a reranker (Day 56) for precise top-order, and the top-k to claude-opus-5. Hybrid fixes recall (both answers get retrieved); the reranker fixes precision (the best one lands at #1).
    
        
    import weaviate, cohere, anthropic

# stage 1: native BM25 + vector hybrid, fused by RRF, in ONE query
res = collection.query.hybrid(query=query, alpha=0.5,       # 0=BM25, 1=vector
                              fusion_type=HybridFusion.RANKED_FUSION, limit=50)
docs = [o.properties["text"] for o in res.objects]

# stage 2: rerank the fused shortlist for precise order (Day 56)
ranked = cohere.Client().rerank(model="rerank-english-v3.0",
                                query=query, documents=docs, top_n=5)
context = "\n\n".join(docs[r.index] for r in ranked.results)

# stage 3: grounded answer
anthropic.Anthropic().messages.create(
    model="claude-opus-5", max_tokens=1024,
    system="Answer only from the provided context. Cite the source.",
    messages=[{"role":"user","content":f"Context:\n{context}\n\nQ: {query}"}])
# hybrid recall -> reranker precision -> grounded generation

🎉 Day 57 of AIFromZero done.
Hybrid search runs a lexical engine and a semantic engine side by side and fuses their rankings. BM25 owns exact keywords, codes and rare terms via idf + saturating tf + length-norm, but is blind to paraphrase. Dense vectors own meaning and synonyms, but blur rare exact tokens. RRF fuses them with nothing but ranks — Σ 1/(k+rank) — so the two engines never need a shared scale, while a weighted sum can win only after you normalize and tune α. The payoff is recall you can't get from either alone: a doc strong in just one list survives. Pair it with a reranker (Day 56) for precision and it's the retrieval front-end of a serious RAG stack. 👉 Tomorrow — Day 58: continuing AIFromZero.
