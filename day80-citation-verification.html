AIFROMZERO · DAY 80

📑 Citation verification — a RAG answer says [c091] and everybody relaxes. There are two checks you can run on that bracket and they catch different things. Citation resolution is pure code — is c091 actually one of the chunks we assembled for this question? Zero model calls, O(citations), exact. Faithfulness is model-scored — does the assembled context actually support the claim? Across 420 seeded answers in 7 defect classes: 🔴 neither check subsumes the other, and the proof is that both off-diagonal cells of the 2×2 are non-empty — 180 answers resolution catches and faithfulness waves through, 60 the reverse. Said as blind spots: resolution cannot see an unsupported claim wearing a valid id (0 of 60 caught) and a context-scoped faithfulness grader cannot see an id that never existed, because the id is not in its input at all (0 of 180 caught). 🔴 The case people get wrong is the real id that was not in this context — it looks real, it resolves perfectly against your chunk store, and only resolution against the assembled context catches it: 60 of 60 one way, 0 of 60 the other. Together the two checks catch 300 of 360 defects where resolution alone gets 240 and faithfulness alone gets 120, and running the free one first removes 240 of 420 model calls.

A citation is two separate promises. The first is that the identifier points at something we actually put in front of the model. The second is that the thing it points at says what the sentence says. They fail independently, they are caught by different machinery at wildly different cost, and a pipeline running only one of them has a named, sizeable blind spot rather than a small one.

1. The 2×2 — and why both off-diagonal cells matter

🔴 This table is the whole page. If either off-diagonal cell were empty, one check would subsume the other and you could drop it. Both are populated, by construction and by measurement: answers where the identifier is wrong and the prose is fine, and where the identifier is fine and the prose is invented. A pipeline that runs one check is not running a cheaper version of the other — it is running a different check whose blind spot is exactly what the other one is for.

2. Per class: exactly which check fires

The 100%/0% pattern is not a rounding artefact, it is what these two checks are. Resolution is a set-membership test, so on a class defined by a bad identifier it is right every time, and on a class defined by bad prose it is silent every time. The grader is the mirror image. 🔴 Read the stale_id row twice: the cited chunk is real, it is sitting in your vector store, it would resolve perfectly against that store — and it was not in the context assembled for this question. Checking membership in the store instead of in the assembled context turns a catch rate into .

3. The two blind spots, stated

Resolution’s blind spot: it never reads the claim. A sentence the context does not support, carrying an id that genuinely is in the context, is a clean pass — of caught. Faithfulness’ blind spot: the grader modelled here is the ordinary context-scoped kind — claim in, assembled chunks in, supported or not out. It is id-blind. An invented identifier, a stale one, or no identifier at all does not change its input by one token, so it answers “supported” and it is right: the content is supported. of caught. Neither number moves by tuning a threshold; both are structural, and the self-check proves the id-blindness directly by swapping a citation and showing the verdict does not budge.

4. Cost — the cheap check is not a cheap approximation

Resolution is a hash-set lookup per citation: comparisons over the whole corpus and zero model calls. Grading every answer costs calls. Run the free check first, grade only what survives, and the bill is — calls removed with the union catch rate unchanged. 🔴 But notice what short-circuiting costs in information rather than money: everything it skips sits in the cell where the answer text was fine. For those the repair is re-citing, not re-answering, and an ordering that dumps them into one undifferentiated “failed” bucket will send correct answers back to the model to be rewritten.

5. The residual: a valid id on the wrong chunk

answers cite a chunk that is in the assembled context and does not support the claim, while some other assembled chunk does. Resolution passes — the id is in the context. Context-scoped faithfulness passes — the context supports the claim. Both are answering their own question correctly; neither question is “does this chunk support this sentence”. The grader that does ask that catches , and it costs one call per citation rather than per answer — here against , and far worse on answers that cite five sources each. It also cannot run at all on a citation that did not resolve: you cannot hand a grader a chunk you could not find. It is a third layer on top of resolution, never a replacement for it.

What this covers, and what it does not

🔴 The entailment check here is a stand-in, not a model. It is a stated token rule: strip the function words from the claim, and count the claim supported by a chunk when at least of the remaining tokens occur in that chunk. Nothing on this page is a claim about how accurate a real faithfulness grader is — real ones are wrong a great deal, and that error is part of why the free check is worth keeping. The page is about what each check can see, and a deterministic stand-in isolates visibility from grader noise. Because the twelve topic vocabularies are disjoint by construction, the stand-in separates supported from unsupported with no overlap at all (); a real grader has no such gap, so read the faithfulness column as a ceiling and the resolution column as exact, because that one is code. The corpus is synthetic: . One claim per answer, one citation per claim, no multi-hop answers, no partial credit, no overlapping chunks, no reranker, no abstention, no quote-span verification. And nothing here asks whether the source is any good — a perfectly resolved, perfectly entailed citation to a wrong document is still wrong, and no check on this page looks at that.

How it works

// check 1 - resolution. No model. This is the entire thing.
const inContext = new Set(answer.assembled);          // ids WE assembled
const resolves  = answer.cites.every(id => inContext.has(id));
const pass      = answer.cites.length > 0 && resolves;

// the bug: checking the STORE instead of the assembled context
const wrong = answer.cites.every(id => store.has(id)); // c091 is real...
                                                       // ...just not here

// check 2 - faithfulness. A model call, and it never sees an id.
const supported = answer.assembled
  .map(id => entails(answer.claim, store.get(id)))
  .some(Boolean);

// the 2x2 that proves neither one subsumes the other
quad[pass ? 0 : 1][supported ? 0 : 1].push(answer.id);

Self-check

Runs on load. The argument is a comparison, so the controls carry it: resolution is checked in both directions over every citation in the corpus (no false accepts and no false rejects), the clean class is checked to raise no alarm from either check, the grader is checked to be genuinely id-blind, and the off-diagonal cells are measured to be non-empty rather than asserted to be.
