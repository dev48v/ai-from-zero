AIFromZero · Day 58

🪗 Prompt Compression — most of your prompt is filler; keep the signal, drop the rest. A long prompt or retrieved context costs money on every call and slows down the prefill — but a large fraction of its tokens carry almost no information: articles, connectives, hedges, boilerplate. Prompt compression (the LLMLingua family from Microsoft) shrinks the text by scoring each token's information value and dropping the lowest-value ones until it hits a target compression ratio, keeping the meaning intact. The score is a perplexity / self-information stand-in: a token a small model finds surprising (rare, high-information) is worth keeping; a token it can predict from context (a stopword, filler) is cheap to throw away. The one rule that makes it safe: never drop the load-bearing tokens — numbers, negations, and named entities — because losing a single "not" or a dollar amount silently flips the instruction. Below is a live, fully self-contained engine over a baked-in support prompt: it scores every token by an inverse-frequency information heuristic, protects the critical tokens, and a compression-ratio slider progressively removes the lowest-value tokens — with a running token count, cost saving, and a "meaning retained?" check. Toggle the guard off, or switch to naive truncation, and watch the meaning break. No API, no LLM, all deterministic.

Squeeze the prompt — keep the meaning.

One baked-in support prompt is scored token-by-token. High-information tokens glow indigo; filler is pale. The three protected classes — numbers, negations, entities — are underlined amber. Prompt compression buys back the tokens filler wastes. A short model scores each token's surprisal, the lowest-value ones are dropped to a budget, and the compressed prompt does nearly the same job at a fraction of the cost and latency. The whole game is knowing what you can afford to lose: stopwords and boilerplate, yes; a number, a negation, or an entity, never — which is exactly what naive truncation (blindly cutting the end) and un-guarded ranking get wrong. This demo uses an inverse-frequency stand-in for perplexity, but the shape is the real thing — LLMLingua and LLMLingua-2 ship this as a library, routinely hitting 2×–5× compression with the answer quality nearly unchanged, and it pairs naturally with retrieval (Day 55/57) and long-context management (Day 52) before the prompt ever reaches Claude.

🔨 Build prompt compression — score, protect, prune

    
Reproduce the LOOK engine as real code: score every token by an information heuristic (a perplexity stand-in), pin the tokens you must never drop, then cut the lowest-value ones to a target ratio. The toy uses inverse-frequency surprisal; the last block swaps in the real LLMLingua-2 compressor and feeds the shrunk prompt to Claude. Every block is the exact idea flowing through LOOK.

    A long prompt, tokenized
    
        
    Compression operates on the context you send every call — a system prompt, retrieved chunks, few-shot examples. Split it into tokens; we keep whole words here, real systems use the model's sub-word tokenizer.
    
        
    prompt = (
  "You are a billing support assistant for Acme Cloud in London. "
  "A customer says invoice INV-4471 for $250 was charged twice on March 3, 2025. "
  "Do not issue a refund without manager approval. Never share the card number. "
  "If fewer than 3 login attempts failed, reset it within 48 hours. "
  "Under the GDPR policy you must delete personal data on request."
)
toks = prompt.split()                 # ~55 tokens; most carry little information

    2
    Score each token by information (a perplexity stand-in)
    
        
    A token's value is how surprising it is — its self-information −log₂ p(token). Rare tokens (a code, a name) score high; a stopword the model can predict from context scores near zero. LLMLingua uses a small LM's perplexity; here inverse frequency is the deterministic stand-in.
    
        
    import math
from collections import Counter

freq = Counter(t.lower().strip(".,") for t in toks)
N = len(toks)
STOP = {"a","an","the","of","to","and","or","is","for","on","in","you","it"}

def info(t):
    key = t.lower().strip(".,")
    surprisal = -math.log2(freq[key] / N)   # rare -> high, common -> low
    if key in STOP:  surprisal *= 0.12       # filler the model can guess back
    return surprisal
# real LLMLingua: perplexity of each token under a small causal LM (GPT-2-ish)

    3
    Protect what you must never drop
    
        
    Low information ≠ droppable. A lone not is common (low surprisal) but load-bearing — losing it flips the instruction. Pin the three critical classes: numbers, negations, named entities. Real systems pass these as force_tokens or run a quick NER pass.
    
        
    import re
NEG = {"not","no","never","without","none","neither","nor","cannot"}

def protected(t):
    key = t.lower().strip(".,")
    is_number = bool(re.search(r"\d", key))               # 250, $250, 48, INV-4471
    is_negation = key in NEG                               # not / never / without
    is_entity = bool(re.match(r"[A-Z]", t)) and t.lower() not in FIRST_WORDS  # Acme, GDPR
    return is_number or is_negation or is_entity
# these tokens are pinned regardless of how low their information score is

  4. 
        
    4
    Rank and cut to a budget (the compression ratio)
    
        
    Pick a ratio r = fraction to remove. Give protected tokens infinite value so they always survive, then drop the round(r·N) lowest-value non-protected tokens. Order is preserved — you keep a readable subset, not a reordering.
    
        
    def compress(toks, r=0.5, protect=True):
    def value(t):
        if protect and protected(t): return float("inf")   # pinned
        return info(t)
    n_remove = round(r * len(toks))
    # indices of the lowest-value tokens (protected ones sort to the end)
    order = sorted(range(len(toks)), key=lambda i: (value(toks[i]), i))
    drop = {i for i in order[:n_remove] if value(toks[i]) != float("inf")}
    return " ".join(t for i, t in enumerate(toks) if i not in drop)

compress(toks, r=0.5)   # ~half the tokens, meaning intact

    The meaning-retained guard
    
        
    Compression is only safe if you can prove nothing critical was lost. Diff the protected set against the survivors — if any dropped, the compression is unsafe at that ratio: raise the budget, or lower r.
    
        
    def meaning_retained(toks, compressed):
    kept = set(compressed.split())
    lost = [t for t in toks if protected(t) and t not in kept]
    return (len(lost) == 0, lost)

ok, lost = meaning_retained(toks, compress(toks, r=0.5))
assert ok, f"critical tokens dropped: {lost}"   # e.g. ['not', '$250'] -> reject

    Contrast: naive truncation loses the tail
    
        
    The lazy way to fit a budget is to cut the end (or middle) of the prompt. It's free — and it silently amputates whatever lives there. Here it drops the GDPR rule and the "do not promise a discount" guardrail entirely, regardless of how important they are.
    
        
    def truncate(toks, r=0.5):
    keep = len(toks) - round(r * len(toks))
    return " ".join(toks[:keep])          # blind — the last r% just disappears

# salience prune keeps the load-bearing "Never share the card number";
# truncation at the same ratio never sees it, and never sees the GDPR rule.
# same token budget, very different meaning.

    Compression ≠ summarization
    
        
    Summarization rewrites (abstractive) — a second LLM call that costs tokens, adds latency, and can hallucinate. Compression selects (extractive) — it only ever deletes existing tokens, so it's cheap, fast, and can't invent facts. Different tools: summarize for humans, compress for the model.
    
        
    # summarization: another model rewrites the text (abstractive)
summary = llm("Summarize:\n" + prompt)     # + cost, + latency, may hallucinate

# compression: keep a subset of the ORIGINAL tokens (extractive)
compressed = compress(toks, r=0.5)          # cheap, deterministic, no new tokens
# LLMs still read compressed (non-fluent) text well - they fill the gaps.

    In practice — LLMLingua-2, then Claude
    
        
    You rarely hand-roll the scorer. LLMLingua / LLMLingua-2 ship a compressor that uses a small model's token importance, honours a target rate, and force-keeps tokens you name. Compress the big context once, then send the shrunk prompt to claude-opus-5 — fewer input tokens, lower cost, faster prefill.
    
        
    from llmlingua import PromptCompressor
import anthropic

compressor = PromptCompressor(
    model_name="microsoft/llmlingua-2-xlm-roberta-large-meetingbank",
    use_llmlingua2=True)

out = compressor.compress_prompt(
    long_context, rate=0.4,                     # keep ~40% of tokens
    force_tokens=["\n", ".", "?", "!"])         # + your numbers / entities
compressed = out["compressed_prompt"]           # out["rate"] reports actual ratio

anthropic.Anthropic().messages.create(
    model="claude-opus-5", max_tokens=1024,
    messages=[{"role":"user","content": f"{compressed}\n\nQ: {question}"}])
# 2x-5x fewer input tokens; answer quality nearly unchanged
