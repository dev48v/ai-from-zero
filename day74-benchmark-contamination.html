The filter length is a window, and it is not where the convention sits

One corpus — items rewritten every few tokens before being copied in — measured by every filter length from the shortest to the longest. flagged is what the report prints. false flags counts clean items the filter deleted. after filter is the score you publish once the flagged items are dropped, against a truth of 0.2500.

The evasion band

Now hold the filter at the conventional length and vary how aggressively the copy was rewritten. run is the longest untouched stretch a rewrite leaves behind — the only thing either the model or the filter can actually see.

The corpus decides the floor

A filter cannot use a short n: on a big corpus a short n-gram appears somewhere by chance, so a short filter deletes a clean benchmark. That floor is arithmetic, and it moves with corpus size. The closed form is validated against the simulator at the sizes this page can actually run, then extrapolated.

A filter length is chosen once and then meets whatever corpus the next model was trained on. If that size is only known to an order of magnitude, the false-flag rate the length actually delivers is an average over the range — a composite-Simpson integral of the closed form over log₁₀(tokens), not a point evaluation.

The control

What is actually being measured

Every quantity on this page comes out of four declared objects and nothing else.

  • An item is k integer tokens drawn uniformly from an alphabet of v. It is a four-choice question, so a model with no knowledge of it scores exactly 1/4 in expectation. Tokens are uniform by declaration — real text is not, and the direction that pushes every number is stated below.
  • A corpus is a pile of documents. Some of them are copies of benchmark items, optionally rewritten: every e-th token replaced by a different token. e = 0 means a verbatim copy.
  • Memorisation length L is the declared abstraction: the shortest contiguous stretch of an item the model must have seen in the corpus for it to answer that item from memory rather than guessing. This page does not claim a value of L for any real model. It shows what happens across the whole range, which is the point — L is a property of the model and nobody publishes it.
  • Filter length n is what a decontamination pass looks for: flag an item if it shares any n consecutive tokens with any corpus document. n is a convention. GPT-3 used 13, other reports use 8, or 50 characters.

Everything follows from one asymmetry: a rewrite every e tokens leaves untouched runs of length e−1. The model benefits when e−1 ≥ L. The filter catches it when n ≤ e−1. Those two inequalities involve different numbers, and only one of them is set by the person publishing the score.

The degeneracy that bounds L from below

The obvious escape is to say the model needs only a very short run, so a short filter would catch everything. Measure it: on a corpus containing no copies at all, how often does an item contain a run of length L that appears somewhere by chance?

The closed form, and exactly where it lies

The chance that a clean item of length k collides with a corpus holding C distinct n-grams is written, everywhere, as if the item’s windows were independent draws:

P(flag) = 1 − (1 − C/vⁿ)k−n+1

The windows are not independent — consecutive windows share n−1 tokens — and neither are the corpus’s grams. So the formula is an approximation, and the honest question is how big the error is. For a single pattern the exact answer is computable: build the KMP automaton for the pattern and count, in exact integer arithmetic, how many length-k strings avoid it.

What a filter does to the error bar

Dropping flagged items does not only change the score, it changes how many items are left to measure it with. On m items a purely guessing model’s observed score is Binomial(m, 1/4)/m, and because 1/4 is a dyadic rational the whole distribution is exact integer arithmetic: P(X ≥ a) = Σ C(m,j)·3m−j / 4m.

Four things that went against the build

What the measurements actually support

  • An n-gram flag rate is a lower bound on contamination, never a certificate. Publishing it as “we found 0.3% contamination” states the filter’s reach, not the corpus’s contents.
  • The filter length and the surviving item count belong next to the score. Both change the number, and one of them changes its error bar.
  • The only design on this page whose reported number is the true number is the one that needs no detector: a benchmark whose items were created after the corpus was collected. Its inflation is bounded by the accidental-overlap floor, which is itself computable in advance.
  • Uniform tokens make this page optimistic. Real text is heavily skewed, so a fixed n collides far more often than the uniform closed form says, which pushes the usable filter length up — the same direction as a bigger corpus, and the same consequence.
