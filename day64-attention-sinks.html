AIFROMZERO · DAY 64

🕳️ Attention sinks — the discovery that a language model devotes a huge share of its attention to the first few tokens, regardless of what they say. Not because they matter, but because softmax must sum to 1: a head with nothing to look at still has to put its mass somewhere, and the earliest tokens are the only ones every position can see. They become a drain. Xiao et al. (2023) noticed the practical consequence: evict those tokens with a sliding window and perplexity does not degrade gracefully, it explodes — while keeping just four of them, plus the recent window, restores it almost entirely. This page implements a real causal attention with RoPE, measures the sink mass directly, then runs three cache policies over the same stream — dense, sliding-window, and StreamingLLM — and reports the distribution shift each one causes, the memory each one uses, and the point at which dense simply runs out. It simulates the cache, never the model: the paper's perplexity numbers are cited separately and never mixed into the live figures.

HOW MANY SINKS ARE ENOUGH?

The paper's answer is four. That is a measurable claim, so measure it: sweep the number of sink slots and watch where the curve flattens. 


      


    

  






  

    


      
Softmax has to put its mass somewhere


      
An attention head produces a probability distribution over the tokens it can see. The
      operative word is probability: it sums to 1, always, whether or not anything in the
      context is relevant.


      
So consider a head whose job is narrow — it fires on quoted speech, say. Most of the time
      there is no quoted speech in view. The head cannot output "nothing"; softmax will not let it.
      It must allocate 1.0 of attention across the tokens available.


      

        
The model's solution is to learn a dump: a few tokens
        whose value vectors contribute almost nothing, so attending to them is close to a no-op. The
        first tokens of the sequence are the natural candidates, because every position can
        see them — under causal masking, position 0 is the only token visible to all.

      


      
These are attention sinks. Their content is irrelevant; their
      position is the whole story.


      
Why this breaks a sliding window

      
Streaming inference needs a bounded cache, and the obvious policy is to keep the most recent
      N tokens. That is correct-looking and it fails badly.


      

        
The moment the window slides past the first few tokens, the sinks are
        evicted. Every head that was dumping its unused mass there must now redistribute it onto
        real tokens — which changes what the model is attending to, everywhere at
        once. Perplexity does not drift; it explodes. The failure is abrupt because
        the eviction of a single position is what triggers it.

      


      
The fix is almost embarrassingly small

      
Keep the first four tokens forever. Slide the window over everything else. That is
      StreamingLLM, and it lets a model generate over millions of tokens with a fixed cache and
      stable perplexity.

      
Four. Not four hundred. The sinks are a mechanism, not a memory — you are not
      preserving information, you are preserving a place for softmax to dump mass into.


      
What StreamingLLM is not

      
It does not extend the model's context. The model still only sees the recent window plus four
      tokens; it has not remembered anything from the middle of the stream. It makes a model
      keep working indefinitely, which is a different property from
      understanding more.

      
That distinction is easy to blur and worth keeping sharp: contrast it with
      yesterday's context extension,
      which changes what positions the model can represent. Neither one gives it more to
      recall.


      
The design consequence

      
If sinks exist because softmax cannot abstain, then give it a way to abstain. Some models now
      train with a dedicated learnable sink token, or with a softmax that has an extra "attend to
      nothing" logit. Both remove the need for the model to co-opt real tokens for the job — and both
      are a direct consequence of taking the explanation seriously rather than just patching the
      symptom.


      
What this page measures

      
Real causal attention, real RoPE, real softmax, over random query/key vectors. That gives
      you the geometric sink — the concentration that follows from causal masking
      alone, because early positions are visible to every later query. Measured here it is real but
      small: about 4% of the mass on the first four tokens, roughly 5.6× what they would get
      by chance.

      

        
And at that strength, StreamingLLM buys nothing. Swapping
        four recent tokens for four sinks is a wash — I measured it, expecting a win, and got none.
        That is not a flaw in the paper; it is the point. The fix works because trained models have a
        much larger sink: they learn near-inert value vectors on those positions and route
        their spare mass there deliberately. The geometric effect is the seat; training is what puts
        the weight on it.

      

      
So the learned sink strength slider adds a declared bias to the first four
      positions' logits, standing in for that learned routing. Set it to 0 and the fix stops working.
      Turn it up and the policy table separates. Being able to switch the effect off is what makes
      the explanation testable rather than decorative — and the paper's perplexity results stay
      cited, never simulated.


    

  






  

    


      
🔨 Build it yourself


      
1. Causal attention, written out

      
function attend(q, keys, positions, dim){
  const logits = keys.map((k, i) => dot(rope(q, posQ, dim), rope(k, positions[i], dim))
                                   / Math.sqrt(dim));
  const max = Math.max(...logits);                 // subtract before exp, always
  const exps = logits.map(l => Math.exp(l - max));
  const sum  = exps.reduce((a, b) => a + b, 0);
  return exps.map(e => e / sum);                   // sums to 1 - that is the whole problem
}

      
The last line is the subject of the page. There is no way for this function to return "I do
      not care about any of these".


      
2. Measure the sink, do not assume it

      
// average attention RECEIVED by each position, over all later queries
const received = new Array(T).fill(0);
for (let t = 1; t < T; t++){
  const a = attend(q[t], keys.slice(0, t + 1), positions.slice(0, t + 1), dim);
  for (let i = 0; i <= t; i++) received[i] += a[i];
}
const sinkMass = received.slice(0, 4).reduce((a, b) => a + b, 0) / totalMass;
const ifEven   = 4 / T;              // what those 4 would get by chance
assert(sinkMass > ifEven);           // the claim, as an inequality


      
3. The three cache policies as index sets

      
const dense    = (t, B, S) => range(0, t + 1);                     // everything
const sliding  = (t, B, S) => range(Math.max(0, t - B + 1), t + 1); // recent only
const streaming = (t, B, S) =>                                      // sinks + recent
  range(0, S).concat(range(Math.max(S, t - (B - S) + 1), t + 1));

      
Writing each policy as "which indices survive" keeps them comparable — same budget, same
      stream, one honest difference.


      
4. Score a policy by what it destroys

      
function evaluatePolicy(policy, T, B, S){
  let massRetained = 0, shift = 0, n = 0;
  for (let t = B; t < T; t++){
    const full = attend(q[t], allKeys(t), allPos(t), dim);   // the truth
    const keep = policy(t, B, S);
    massRetained += keep.reduce((a, i) => a + full[i], 0);

    const kept = renormalise(keep.map(i => full[i]));        // what the model now sees
    shift += totalVariation(kept, restrictAndRenorm(full, keep));
    n++;
  }
  return { massRetained: massRetained / n, shift: shift / n };
}


      
5. The comparison that makes the point

      
// SAME budget. The only difference is that streaming spends 4 slots on position.
const sw = evaluatePolicy(sliding,   T, 128, 0);
const st = evaluatePolicy(streaming, T, 128, 4);
assert(st.massRetained > sw.massRetained);   // 4 slots buy back a lot of mass
assert(st.shift        < sw.shift);

      
Both use 128 entries. Streaming gives up four recent tokens and gets the sinks in exchange,
      and that trade is strongly positive — which is the entire finding.


      
6. Sweep the sink count

      
The paper says four. Do not take it: sweep 0 to 16 and find where the curve flattens. If your
      measurement says four is the elbow, you have reproduced the result rather than repeated it.


      
7. Be clear about what you have simulated

      
// This measures the GEOMETRIC sink: the concentration that follows from causal
// masking and position alone, with random q/k. Trained models show a far larger
// effect because their VALUE vectors on those positions are learned to be
