AIFromZero · Day 55

✂️ Semantic Chunking — how you split a document for RAG decides how good the answers are. Retrieval-augmented generation never feeds the whole document to the model; it feeds chunks. The naive way — fixed-size chunking — cuts every N characters or sentences regardless of meaning, so it slices straight through the middle of a thought: half an idea lands in chunk 4, the other half in chunk 5, and neither is retrievable as a complete answer. Semantic chunking splits where the meaning changes instead. Embed each sentence, measure how similar each sentence is to the next, and put a breakpoint wherever adjacent similarity drops — the seam between two topics — so every chunk is one coherent idea. The control is a breakpoint percentile: split only at gaps whose dissimilarity sits in the top (100−p)%, so a lower percentile splits more aggressively. Below is a live, fully self-contained demo over a baked-in three-topic document — a lightweight TF-IDF bag-of-words embedding + cosine similarity computed in your browser, no API, no LLM, deterministic. Slide the percentile and watch the sentence strip re-colour into semantic chunks, watch the adjacent-similarity sparkline with its live threshold line, compare side-by-side against fixed-size chunking, and see which chunk a retrieval query actually pulls.

Split at the seams of meaning, not every N characters.

The sample document below runs three topics back to back — photosynthesis, then the Roman empire, then espresso. Each sentence is embedded (TF-IDF bag-of-words), adjacent sentences are compared by cosine, and a breakpoint drops in wherever similarity falls below a threshold set by the breakpoint percentile. Slide it and the semantic chunks re-form live; compare against fixed-size chunking that ignores meaning entirely. Semantic chunking is the fix for the quiet failure mode of RAG: retrieval can only return what chunking left intact. Fixed-size chunks cut mid-thought, so the answer you need gets split across two chunks and the top-1 result is half a story. Splitting at the seams of meaning — where adjacent-sentence similarity drops below a percentile-set threshold — keeps each chunk to one idea, so the retrieved chunk is a complete, self-contained answer. It costs an embedding pass over every sentence, and the percentile (plus a little overlap) is the dial between too-few giant chunks and too-many fragments. Everything above is a deterministic, no-network toy — TF-IDF instead of a neural embedder — but the mechanism is exactly the real one.

🔨 Build the semantic chunker — embed, compare, split at the drop

    
Reproduce the LOOK engine as real code: split into sentences, embed each one (a hashing / TF-IDF bag-of-words, exactly like the demo — no API), measure adjacent-sentence cosine, turn similarities into a breakpoint percentile threshold, split where the gap dips below it, then contrast with fixed-size chunking and wire the result into a real RAG call. Every block is the exact idea flowing through LOOK.

    Split the document into sentences
    
        
    Semantic chunking works at the sentence level — the atom that carries one small idea. Split on sentence boundaries first; the chunker's job is deciding where consecutive sentences stop belonging together.
    
        
    import re

def split_sentences(doc: str) -> list[str]:
    # Split on ., !, ? followed by whitespace. Real pipelines use spaCy /
    # nltk / a regex like this; the point is one idea per unit.
    parts = re.split(r'(?<=[.!?])\s+', doc.strip())
    return [s.strip() for s in parts if s.strip()]

sents = split_sentences(document)   # -> ["A plant makes energy...", ...]

    2
    Embed each sentence — TF-IDF bag-of-words (no API)
    
        
    The demo embeds with a lightweight TF-IDF bag-of-words — deterministic, no network. Tokenize, drop stopwords, weight each term by tf · idf so topic-specific words (photosynthesis, espresso) dominate and filler doesn't. In production you swap this one function for a neural embedder; everything downstream is unchanged.
    
        
    import math
from collections import Counter

STOP = set("a an the of to and or in on at is are was were be it its this "
           "that with for as by from into then so such can will just".split())

def tokenize(s):
    return [w for w in re.sub(r'[^a-z0-9\s]', ' ', s.lower()).split()
            if len(w) > 1 and w not in STOP]

def tfidf_vectors(sents):
    toks = [tokenize(s) for s in sents]
    n = len(sents)
    df = Counter(w for t in toks for w in set(t))          # doc frequency
    vecs = []
    for t in toks:
        tf = Counter(t)
        vecs.append({w: c * (math.log((1 + n) / (1 + df[w])) + 1)   # tf * idf
                     for w, c in tf.items()})
    return vecs

vecs = tfidf_vectors(sents)   # one sparse dict per sentence

    Adjacent-sentence cosine similarity
    
        
    Walk the sentences in order and measure how similar each one is to its neighbour. High similarity = same topic continuing; a sharp drop = the seam between two ideas. This sequence of n−1 numbers is the entire signal the chunker splits on.
    
        
    def cosine(a, b):
    dot = sum(v * b.get(w, 0.0) for w, v in a.items())
    na = math.sqrt(sum(v * v for v in a.values()))
    nb = math.sqrt(sum(v * v for v in b.values()))
    return dot / (na * nb) if na and nb else 0.0

def adjacent_sims(vecs):
    return [cosine(vecs[i], vecs[i + 1]) for i in range(len(vecs) - 1)]

sims = adjacent_sims(vecs)
# e.g. [0.55, 0.41, 0.60, 0.00, 0.48, ...] -> the 0.00 is a topic change

    The breakpoint-percentile threshold
    
        
    Work in distance (1 − similarity): a topic change is a big distance. Rather than a fixed cutoff, set the threshold at a percentile of all the gap distances — p=85 splits only the top 15% biggest jumps. A lower percentile lowers the bar, so more gaps qualify and you get more chunks. This is LangChain's breakpoint_threshold_type="percentile".
    
        
    def percentile(xs, p):
    s = sorted(xs)
    if not s: return 0.0
    i = (p / 100) * (len(s) - 1)
    lo, hi = math.floor(i), math.ceil(i)
    return s[lo] + (s[hi] - s[lo]) * (i - lo)   # linear interpolation

def breakpoints(sims, p=85):
    dist = [1 - s for s in sims]
    thr  = percentile(dist, p)
    return {i for i, d in enumerate(dist) if d >= thr}   # gaps to cut after

# lower p -> lower thr -> more gaps clear it -> more, smaller chunks

  5. 
        
    5
    Split at the breakpoints → semantic chunks
    
        
    Walk the sentences; a breakpoint after sentence i starts a new chunk at i+1. Everything between two breakpoints is one coherent, self-contained chunk — exactly the coloured boxes in LOOK.
    
        
    def semantic_chunks(sents, p=85):
    vecs  = tfidf_vectors(sents)
    sims  = adjacent_sims(vecs)
    brks  = breakpoints(sims, p)
    chunks, cur = [], [sents[0]]
    for i in range(len(sents) - 1):
        if i in brks:                 # seam between sentence i and i+1
            chunks.append(" ".join(cur)); cur = []
        cur.append(sents[i + 1])
    chunks.append(" ".join(cur))
    return chunks

for c in semantic_chunks(sents, p=85):
    print("•", c)   # each chunk stays on one topic

    The baseline: fixed-size chunking cuts mid-thought
    
        
    Contrast it with the naive method: pack sentences until a character budget is hit, then cut. It's fast and needs no embeddings, but the boundary lands wherever the counter runs out — often straight through a topic, so one idea is split across two chunks and neither is a complete answer.
    
        
    def fixed_chunks(sents, size=200):
    chunks, cur, n = [], [], 0
    for s in sents:
        if n and n + len(s) > size:      # budget exceeded -> cut here
            chunks.append(" ".join(cur)); cur, n = [], 0
        cur.append(s); n += len(s) + 1
    if cur: chunks.append(" ".join(cur))
    return chunks

# "recursive" chunking is the middle ground: try to break on paragraph,
# then sentence, then word boundaries before falling back to a hard cut.

    Chunk size & overlap — the tradeoff dial
    
        
    Chunks too big dilute the embedding and stuff the prompt with irrelevance; too small and a fact loses its surrounding context. A little overlap (repeat the last sentence or two into the next chunk) hedges against a breakpoint that split a fact from its explanation. Semantic chunking gets the boundaries right; size and overlap tune how much context rides along.
    
        
    def with_overlap(chunks_of_sents, k=1):
    "Prepend the last k sentences of each chunk to the next one."
    out = []
    for j, ch in enumerate(chunks_of_sents):
        prefix = chunks_of_sents[j - 1][-k:] if j else []
        out.append(prefix + ch)
    return out

# Rules of thumb:  ~1-3 sentences of overlap; cap chunk size so a giant
# semantic block still fits the retriever's context and stays specific.

    In practice — real embeddings, then answer with Claude
    
        
    Swap the TF-IDF toy for a real embedder (Anthropic has no embeddings endpoint — it recommends Voyage AI; or use LangChain's SemanticChunker), index the chunks in a vector store, retrieve the top few for a query, and hand them to claude-opus-5. Because the chunks are semantically clean, the retrieved context is a complete answer, not half of one.
    
        
    import anthropic, voyageai

vo     = voyageai.Client()          # real neural embeddings
client = anthropic.Anthropic()

# 1) chunk semantically (Steps 1-5)  2) embed + index each chunk
chunks = semantic_chunks(split_sentences(document), p=90)
index  = vo.embed(chunks, model="voyage-3", input_type="document").embeddings

# 3) retrieve the best chunk for a query, 4) answer with Claude
q  = vo.embed([query], model="voyage-3", input_type="query").embeddings[0]
best = max(chunks, key=lambda c, e=iter(index): _cos(q, next(e)))

msg = client.messages.create(
    model="claude-opus-5", max_tokens=1024,
    thinking={"type": "adaptive"},
    system="Answer only from the provided context. Cite the chunk.",
    messages=[{"role": "user",
               "content": f"Context:\n{best}\n\nQuestion: {query}"}],
)
# The retrieved chunk is one whole idea -> the model has what it needs.
