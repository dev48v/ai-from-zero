AIFromZero · Day 44

🌀 Model Collapse — what happens when AI learns from AI. Train a model on data made by the previous model, then repeat — generation after generation. Each round only ever sees a finite sample, so the rare cases (the tails) vanish first; then a simple model smears the leftover structure toward the average; and the spread shrinks a little every generation. Compound that over many rounds and everything converges to a bland, narrow blob — the model has forgotten the diversity of the real world. The fix is refreshingly simple: keep real human data in the mix.

Start with a rich world, then let a model train on its own output — over and over

The gray shape below is the real distribution — two big populations, a rare subgroup near 5, and a heavy tail out past 8. Generation 0 is a finite sample of it. Then each generation does exactly two things, live in your browser: fit a simple model (just a mean and a variance) to the current sample, and resample a fresh batch from that fit — which becomes the next generation's training data. No real data is looked at again. Watch the rare cases die, the histogram narrow toward the average, and the spread shrink every round. Then flip on "mix in real data" and watch the bleeding stop. 🔎 Why the green line survives. A single generation of the pure loop shrinks variance by a factor of about (n−1)/n — tiny, but it compounds every round until the spread hits zero. Mixing in even a modest slice of real data resets that: each generation re-injects genuine tails and spread, so the recursion settles at a stable floor instead of vanishing. This is the core defence against model collapse — never train purely on your own output; keep anchoring to originals.

Model collapse is what happens when generative models are trained, generation after generation, on data produced by earlier models. Three errors compound: finite samples miss the rare tails, a limited model can't represent the full structure, and estimation error nudges the spread down each round. The result is a distribution that first loses its rare cases, then narrows toward the average, until everything looks the same. As the open web fills with AI-generated text and images, this is a real risk for the next round of training — which is why genuine human data is becoming precious, and why the practical fix is to keep real data in the mix, filter synthetic data, and accumulate rather than replace (it pairs directly with Day 39, Synthetic Data).

    The "real world" — a rich distribution with rare cases and a tail
    
        
    Real data is diverse: common patterns, minority subpopulations, and rare long-tail events. We model it as a mixture — two big modes, a rare subgroup, and a heavy tail — so there's genuine structure for a collapse to destroy.
    
        
    // the real distribution = a mixture of Gaussians (weight, mean, std)
const REAL = [
  { w:0.45, m:-2.0, s:0.55 },   // big population A
  { w:0.40, m: 2.0, s:0.55 },   // big population B   -> bimodal
  { w:0.12, m: 5.0, s:0.50 },   // a RARE subpopulation
  { w:0.03, m: 8.0, s:0.50 },   // the heavy TAIL (extreme cases)
];
function sampleReal(){
  let r = Math.random(), acc = 0;
  for (const c of REAL){ acc += c.w; if (r <= acc) return gauss(c.m, c.s); }
  return gauss(8, 0.5);
}
const gauss = (m,s) => m + s*Math.sqrt(-2*Math.log(1-Math.random()))*Math.cos(2*Math.PI*Math.random());

    The generative model — fit, then resample
    
        
    Our "model" is deliberately simple: estimate a mean and a variance from the sample, then generate new data by drawing from that single Gaussian. Two things to notice: a single Gaussian cannot represent two modes or a tail (it will smear them into the average), and we fit variance with the maximum-likelihood estimator (divide by n), which is biased slightly low on a finite sample.

    Why it collapses — the variance shrinks every generation
    
        
    Here's the maths. If you draw n points from a distribution of variance V, the expected ML-estimated variance of that new sample is ((n-1)/n)·V — a hair smaller. Feed that back in as the new truth and it compounds: after t generations the spread is ((n-1)/n)^t of the original, heading to zero. The tails go first (extreme values are rarest, so a finite sample almost never keeps them), then the whole thing narrows toward a single average value.
    
        
    // each generation multiplies the variance by ~ (n-1)/n  < 1
//   var_after ≈ (n-1)/n * var_before          (compounds every round)
//   var_t     ≈ ((n-1)/n)^t * var_0    ->  0  (collapse)
// smaller n  -> factor further below 1 -> collapses FASTER.
//
// even an UNBIASED estimator collapses: variance becomes a positive
// random walk whose only stable resting point is 0 (it is absorbing).
// three compounding errors (Shumailov et al.):
//   1. sampling error  - finite samples miss the rare tails
//   2. expressivity    - a simple model can't hold the real structure
//   3. estimation error- fitted stats drift, with no correction signal

    The fix — keep real data in the mix
