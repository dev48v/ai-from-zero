Cost routing — sending the easy requests to the cheap model, and the one metric that stops you fooling yourself about whether it worked.

Two models, one queue, and a decision per request

A small model costs a fraction of a large one and gets most easy requests right. A router that could tell easy from hard would cut the bill dramatically. Every production LLM system reaches this point, and the argument that follows is always about accuracy versus cost — which is the wrong frame, because you can buy any accuracy you like by spending more.

Cost per correct answer is the usual proposed fix, and on its own it is worse than useless: it hands the prize to the cheapest model that is vaguely adequate, every time. On the traffic below it picks the small model outright — 74% accurate, and the cheapest answer anyone ever bought.

The question only becomes answerable once you fix a quality floor: given the accuracy you have promised, which strategy reaches it for the least money? That is a question routing can genuinely win, and it is the one the tables below ask.

The router is not free

Most comparisons quietly price the router at zero. It is a model call too, or at least an embedding lookup, and on a cheap-enough workload it can cost more than it saves. The table re-runs the best strategy with the router's own cost charged honestly.

Routing on the small model's confidence

The obvious design: ask the small model, and escalate when it says it is unsure. It is cheap, it needs no training, and it fails exactly where it matters — on the requests where the small model is confidently wrong. Those are precisely the ones a router must catch, and confidence is blind to them by construction.

Cascade versus upfront routing

A cascade always runs the small model first and escalates on a verifier's say-so, so it pays twice for every hard request. Upfront routing decides before spending anything, so it pays once — but it has less to go on, because it has not seen an answer yet.

Where the ceiling is

An oracle router knows in advance which requests the small model will get right, and sends only the rest. No real router can beat it, and the gap between your router and the oracle is the only honest measure of how much routing skill you have left to gain.
