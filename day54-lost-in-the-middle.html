AIFromZero · Day 54

🕳️ Lost in the Middle — an LLM does not read a long context evenly. Bury a single fact — a needle — inside a long stack of documents and ask the model to retrieve it, and how reliably it succeeds depends heavily on where the fact sits. Facts at the very start of the context (primacy) or the very end (recency) are recalled reliably; a fact in the middle is far more likely to be missed. Plot accuracy against needle position and you get a U-shaped curve — high at both edges, sagging in the middle — the finding of Liu et al., 2023, "Lost in the Middle: How Language Models Use Long Contexts." And it gets worse as the context grows: the more documents you stuff in, the deeper the middle sags — so a 100k-token window does not mean 100k tokens of usable attention. Long context ≠ used context. Below: place a needle at any position among N documents, slide the context length up, and a baked-in, deterministic position-accuracy model shows retrieval collapsing in the middle and worsening as the context grows. Plot the U-curve, watch the document heat-map, toggle model profiles, and roll seeded retrieval trials — no network, no LLM, seeded and reproducible.

Lost in the middle is why "it's in the context" is not the same as "the model used it." Retrieval accuracy traces a U across position — strong at the edges (primacy + recency), weak in the middle — and the middle collapses further as the context grows, because the background retrievability of an interior document decays with total length. The fixes are structural, not magical: reorder by relevance so the best evidence lands at the top and bottom, rerank retrieved chunks with a cross-encoder and keep only the few that matter, and put the key facts at the edges of the prompt. Everything above is a deterministic, seedable toy model — no LLM, no network — but the shape is real.

🔨 Build the lost-in-the-middle model — position, decay, U-curve, mitigations

    
Reproduce the LOOK engine as real code: model a document's retrieval accuracy from its position, add primacy + recency to lift the edges, let a length-dependent floor crush the middle, sweep positions to draw the U, roll seeded needle-in-a-haystack trials, and then fix it by reordering retrieved chunks so the best evidence lands at the edges. Every block is the exact idea flowing through LOOK.

    
    
      
  1. 
        
    1
    Retrieval accuracy is a function of position
    
        
    Place the needle in document i of N and map it to a relative position r = (i-1)/(N-1) in [0,1] — 0 = very first document, 1 = very last. The whole phenomenon is: accuracy depends on r, not just on whether the fact is present.
    
        
    def rel_pos(i: int, n: int) -> float:
    "Document i (1-indexed) of n -> relative position in [0, 1]."
    return 0.0 if n <= 1 else (i - 1) / (n - 1)

# r = 0.0  -> very start (primacy)
# r = 0.5  -> dead centre (the danger zone)
# r = 1.0  -> very end (recency)
    
      
    2. 
      
  2. 
        
    2
    Primacy + recency lift the edges
    
        
    Two Gaussian bumps: primacy peaks at the start and decays inward; recency peaks at the end and decays inward. The edge advantage at a position is whichever bump is stronger there. In the middle both have decayed to ~0, so there is no advantage — that is the sag.
    
        
    import math

def primacy(r, strength=0.97, width=0.28):
    "Strong at r=0, fades toward the middle."
    return strength * math.exp(-(r / width) ** 2)

def recency(r, strength=1.00, width=0.22):
    "Strong at r=1, fades toward the middle."
    return strength * math.exp(-((1 - r) / width) ** 2)

def edge_advantage(r):
    return max(primacy(r), recency(r))   # 0..~1; ~0 in the middle
# recency > primacy here -> the end edge is a touch higher than the start
    
      
    3. 
      
  3. 
        
    3
    Context length crushes the middle
    
        
    A middle document has no edge advantage — its accuracy is just the background floor, the odds the model attends to an arbitrary interior chunk. That floor decays as the context grows: more documents means the middle competes for less attention. This is the "worse as context grows" half of the phenomenon.
    
        
    def middle_floor(n, floor0=0.85, k=0.055):
    "Background retrievability of an interior doc; decays with length."
    return floor0 * math.exp(-k * (n - 1))

middle_floor(5)   # ~0.68  short context -> middle is still findable
middle_floor(24)  # ~0.30  the middle is sagging
middle_floor(60)  # ~0.03  the middle has effectively vanished
    
      
    4. 
      
  4. 
        
    4
    The full position → accuracy U-curve
    
        
    Combine them: start at the floor, then let the edge advantage lift you toward 1. acc = floor + (1 - floor) · edge. At the edges edge≈1 so acc≈1; in the middle edge≈0 so acc≈floor. Deterministic, no NaN, always U-shaped.
    
        
    def accuracy(i, n, floor0=0.85, k=0.055):
    r = rel_pos(i, n)
    floor = middle_floor(n, floor0, k)
    acc = floor + (1 - floor) * edge_advantage(r)
    return max(0.02, min(0.995, acc))       # clamp: never 0, never 1

# n=24: start -> ~0.99, middle -> ~0.30, end -> ~1.00   (a clean U)
# A bigger base model = higher floor0 + smaller k = a flatter, higher U.

    Sweep positions → the U-curve data
    
        
    The LOOK chart is just accuracy evaluated across every position for a fixed n. Sweep i from 1 to n and you get the curve: high, low, high. Sweep across several n and the middle drops as n rises — the exact behaviour Liu et al. measured on real models.
    
        
    def u_curve(n):
    return [accuracy(i, n) for i in range(1, n + 1)]

for n in (5, 24, 60):
    c = u_curve(n)
    print(n, round(min(c), 2), "at pos", c.index(min(c)) + 1)
# 5  0.68 ...   24 0.30 ...   60 0.03 ...  -> minimum sits near the centre,
# and gets deeper as n grows. Edges stay high throughout.

    Seeded needle-in-a-haystack trials
    
        
    The "needle test" (Kamradt) makes this empirical: hide one fact, ask for it, score hit/miss, repeat across positions and lengths. Our toy version draws Bernoulli(accuracy) trials from a seeded PRNG so the run is deterministic and reproducible — same seed, same chips.
    
        
    import random

def needle_trials(i, n, seed=0xA53, trials=16):
    rng = random.Random(seed)
    p = accuracy(i, n)
    hits = sum(1 for _ in range(trials) if rng.random() < p)
    return hits, trials, p

needle_trials(12, 24)   # e.g. (5, 16, 0.30)  -> found 5/16, mostly missed
needle_trials(1, 24)    # e.g. (16, 16, 0.99) -> found every time (edge)
# Same seed -> identical hit/miss pattern, every run.

    Mitigation: reorder / rerank so the best evidence sits at the edges
    
        
    If accuracy depends on position, control the positions. Rerank retrieved chunks by relevance (a cross-encoder scores each against the query), then interleave the top ones onto the edges of the prompt — best-and-second at the start and end, weakest buried in the middle where a miss costs least. This is the standard RAG fix.
    
        
    def rerank(chunks, query, scorer):
    "Cross-encoder / reranker scores (query, chunk) relevance."
    return sorted(chunks, key=lambda c: scorer(query, c), reverse=True)

def edge_first_order(ranked):
    "Put the most relevant chunks at the START and END, weakest in the middle."
    head, tail = [], []
    for idx, chunk in enumerate(ranked):
        (head if idx % 2 == 0 else tail).append(chunk)
    return head + list(reversed(tail))   # best -> edges, worst -> middle

ordered = edge_first_order(rerank(chunks, query, cross_encoder))
# Now the fact you care about lands where the model actually reads.

    In practice — the real toolkit
    
        
    On a real model you don't hand-roll the U — you work around it: retrieve fewer, better chunks; rerank with a cross-encoder (Cohere Rerank, bge-reranker, a fine-tuned scorer); place the strongest evidence at the top and bottom of the prompt; and keep the key instruction/answer near an edge. Below, a Claude call with the reranked, edge-first context assembled — the fact is where the model reads.
    
        
    import anthropic
client = anthropic.Anthropic()

# 1) retrieve, 2) rerank by relevance, 3) put the best at the edges
ranked  = rerank(retrieve(query, k=40), query, cross_encoder)[:8]
context = "\n\n".join(edge_first_order(ranked))   # best -> start & end

msg = client.messages.create(
    model="claude-opus-5", max_tokens=1024,
    thinking={"type": "adaptive"},
    system="Answer only from the provided context. Cite the document id.",
    messages=[{"role": "user",
               "content": f"Context:\n{context}\n\nQuestion: {query}"}],
)
# The needle now sits near an edge, not buried in the middle -> it gets read.
# Rerankers: Cohere Rerank, bge-reranker-v2, Voyage rerank, or a fine-tuned CE.
