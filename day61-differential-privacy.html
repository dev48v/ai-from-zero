AIFromZero · Day 61

🔒 Differential privacy — start with the thing everybody gets wrong: “anonymised” is not a property a dataset can have. Strip the names and you have not removed the identity, you have moved it into the combination of everything else. Latanya Sweeney showed in 1997 that ZIP code, date of birth and sex alone identify most Americans uniquely, and used exactly that to pull the Governor of Massachusetts’s medical record out of a “de-identified” hospital release and post it to him. Netflix’s anonymised ratings fell to a join against public IMDb reviews. The 2020 US Census reconstructed 245 million people’s records from its own published tables. Every one of those releases was anonymised in the way the word is normally used, and the re-identification lab below reproduces the attack live on a synthetic table so you can watch it happen. The trap is that privacy was being treated as a property of the data, when an attacker’s power depends on what they already know — and you cannot enumerate that. Differential privacy escapes by moving the guarantee onto the mechanism instead: a randomised algorithm M is ε-differentially private if for every pair of databases D, D′ differing in one person and every possible output set S, Pr[M(D) ∈ S] ≤ eε · Pr[M(D′) ∈ S]. Read it as a promise made to you personally: whatever anyone concludes, they would have concluded almost exactly the same thing had your row never existed, so joining the dataset cannot hurt you by more than a factor eε — which is why an adversary’s ability to tell whether you were in it is capped at eε/(1+eε), a bound this page measures rather than quotes. Getting there costs calibrated noise: compute the query’s sensitivity Δf — the most one person can move the answer — and add Laplace(Δf/ε), whose worst-case log-likelihood ratio is exactly ε everywhere, or Gaussian noise with σ = Δf√(2ln(1.25/δ))/ε, which has no finite worst case at all — that is precisely what δ is buying. And ε is a budget that is spent, not a setting: ask k questions and the losses add, so the page runs sequential and advanced composition against the measured total loss. Below, every distribution is sampled hundreds of thousands of times in your browser and checked against its closed form — including a null control that shows what the measurement instrument reports when the true privacy loss is zero. No libraries, 433 assertions verified in Node against analytic CDFs, closed-form tail probabilities and brute-force re-identification counts.

The null control runs the same estimator on two independent samples from the same distribution, where the true privacy loss is exactly zero. Whatever it reports is pure measurement noise — so the measured loss is only meaningful to that precision, and at very small ε the instrument is the limiting factor rather than the mechanism. An attacker sees one output and must decide whether Alice was in the database. Prior 50/50, Bayes-optimal strategy (the likelihood-ratio test), — independent trials. Differential privacy caps the accuracy at eε/(1+eε). The measured value sits below the cap, because the cap is the worst case over all outputs while the attacker has to live with the average.

5 · No trusted curator at all — randomised response

Everything above assumes somebody holds the raw data and adds the noise. Local differential privacy removes that assumption: each person randomises their own answer before it leaves their device, so the collector never sees a true value. Warner invented it in 1965 for surveys about embarrassing questions, decades before anyone wrote down the definition it satisfies. Below, — simulated people answer a sensitive yes/no question; each tells the truth with probability p and lies otherwise, which is exactly ε = ln(p/(1−p))-DP. The raw tally is biased — and a single subtraction removes the bias exactly.

truth probability p0.70

Four flavours you will meet in a real paper
Pure ε-DP
Laplace noise. No exceptions at all: the log-likelihood ratio is bounded by ε at every output, so δ is exactly 0. The strongest promise, the fattest tails, and composition that adds up fast.
(ε,δ)-DP
Gaussian noise. Thinner tails, better composition, and a genuine escape hatch: with probability δ there is no bound whatsoever. Keep δ well below 1/n — at δ = 1/n a mechanism that publishes one random person in full is technically compliant.
Rényi-DP / zCDP
Bound the Rényi divergence at every order instead of the worst case. Composition becomes simple addition, which is why every real DP-SGD accountant uses it and converts to (ε,δ) only at the very end.
Local & shuffle DP
No trusted curator: noise added on the device. Enormously more noise for the same ε — error grows like √n rather than staying constant. The shuffle model recovers much of the gap by anonymising the order of reports.

    Run the attack first — a join is all it takes
    
        
    Before writing any mechanism, reproduce the thing it exists to prevent. Take a “de-identified” release and an auxiliary table that shares a few innocuous columns, group the release by that shared key, and see how many groups contain exactly one person. Those are named. The auxiliary table does not have to be a voter roll — a public review site, a fitness leaderboard, a delivery address, a photo timestamp all work, and that is the point: the attacker chooses the auxiliary data after you publish, so you are defending against a set you cannot enumerate.
    
        
    QID = ("zip", "birth_date", "sex")        # nothing sensitive. all public.

groups = defaultdict(list)
for row in released: groups[key(row, QID)].append(row)

named = 0
for person in voter_roll:                 # bought, or scraped, or leaked
    hits = groups.get(key(person, QID), [])
    if len(hits) == 1:                    # unique quasi-identifier
        named += 1                        # name + diagnosis, together

# Sweeney 1997: ZIP + DOB + sex identifies ~87% of the US population.
# On the synthetic 600-row release on this page it names over 95%.

    k-anonymity, and the attack that walks straight past it
    
        
    The obvious repair is to generalise until every quasi-identifier group contains at least k people. It genuinely stops naming. It does nothing about the sensitive column: if all k people in a group share a diagnosis, the attacker learns the diagnosis of anyone they can place in that group, without ever identifying a row. That is the homogeneity attack. l-diversity added a requirement on the spread of sensitive values, t-closeness added one on its distribution, and both fell to attackers holding better background knowledge. Each patch answers one attack; none of them can answer “what else does the attacker know?”, which is the only question that matters.
    
        
    def k_anonymity(rows, qid):
    g = groupby(rows, key=lambda r: key(r, qid))
    return min(len(v) for v in g.values())

def homogeneous_groups(rows, qid, sensitive):        # k-anonymous and STILL leaking
    return [v for v in groupby(rows, key(qid)).values()
            if len(v) >= 2 and len({r[sensitive] for r in v}) == 1]

# and the result that ends the argument (Dinur-Nissim 2003):
# answer enough SUBSET-SUM queries too accurately and the whole database
# can be RECONSTRUCTED. accuracy and privacy are not independent knobs.
# the 2020 US Census reconstructed 245 million records from its OWN tables.

    The definition, as code you can evaluate
    
        
    A randomised mechanism M is ε-differentially private if for every pair of neighbouring databases and every output set, Pr[M(D)∈S] ≤ e^ε · Pr[M(D′)∈S]. The useful reformulation is the privacy loss random variable: L(x) = ln(P_D(x)/P_D′(x)). Pure ε-DP says |L(x)| ≤ ε for every x — not on average, not with high probability, everywhere. Two things follow immediately. It is a property of the mechanism, not of any dataset, so it holds against attackers you have never imagined. And it says nothing about what the world learns in general — if smoking causes cancer, a DP study reveals that, and it would have revealed it whether or not you were in it. DP protects your participation, which is the only thing you actually control.
    
        
    # the quantity everything is really about
def privacy_loss(x, D, D_prime, M):
    return log(M.density(x, D) / M.density(x, D_prime))

# pure eps-DP:      max over ALL x of |privacy_loss| <= eps      (delta = 0)
# (eps, delta)-DP:  Pr[ privacy_loss > eps ] <= delta            (an escape hatch)

# neighbouring = differ in one person. two conventions, and they matter:
#   bounded    -- same n, one row's VALUE changes    (sensitivity often 2x)
#   unbounded  -- one row added or removed           (used on this page)
# a paper that does not say which one is not stating a guarantee.

    Sensitivity — computed, never guessed
    
        
    Sensitivity is the bridge from a question to a noise scale: Δf = max |f(D) − f(D′)| over all neighbouring pairs. A counting query has Δf = 1, because one person can only be in or out. A sum over an unbounded column has infinite sensitivity — one billionaire moves it arbitrarily far — so you must clip first, and the clip bound becomes the sensitivity. That is not a preprocessing detail, it is the privacy parameter, and choosing it from the data without paying for that choice is a real and common leak. Note the free win in a histogram: one person lands in exactly one bucket, so the entire histogram costs ε, not ε per bucket. That is parallel composition, and it applies to any query decomposed over disjoint subsets.
    
        
    def sensitivity_bruteforce(f, D):            # a real test, not a claim
    base = f(D)
    return max(abs(base - f(D[:i] + D[i+1:])) for i in range(len(D)))

count  = lambda D: sum(1 for r in D if r.diag == "HIV")     # delta_f = 1
total  = lambda D: sum(min(C, r.income) for r in D)         # delta_f = C  (clip!)
mean_  = lambda D: total(D) / len(D)                        # delta_f = C/n

# assert sensitivity_bruteforce(count, D) <= 1
# a histogram over DISJOINT buckets costs eps TOTAL, not eps per bucket.

    The Laplace mechanism — and sampling it correctly
    
        
    Add Laplace(Δf/ε). The proof is one line and worth doing once: the density ratio between the two shifted Laplaces is exp((|x−a′|−|x−a|)/b), the triangle inequality caps the exponent at |a−a′|/b ≤ Δf/b, and setting b = Δf/ε makes that exactly ε. The double-exponential shape is not aesthetic — it is the shape whose log-density is piecewise linear, which is what makes the ratio bounded everywhere. Sample it by inverse transform from one uniform; never by subtracting two exponentials from a library you have not checked. And on a real deployment, remember that floating-point Laplace sampling is attackable: the gaps in the float grid leak bits, which is why production code uses the discrete/snapping variants.
    
        
    def laplace(b, u):                       # u ~ Uniform(-0.5, 0.5)
    return -b * sign(u) * log(1 - 2*abs(u))

def dp_count(D, predicate, eps):
    return sum(map(predicate, D)) + laplace(1.0 / eps, uniform(-.5, .5))

# why b = delta_f / eps, in one line:
#   P_D(x) / P_D'(x) = exp( (|x-a'| - |x-a|) / b ) <= exp( |a-a'| / b )
#                                                  <= exp( delta_f / b ) = e^eps
# E|noise| = b = delta_f/eps.  halve eps, double the error. no way around it.
# PRODUCTION: naive float sampling leaks through the float grid (Mironov 2012).

    Audit it empirically — and run the null control
    
        
    Do not take the formula's word for it. Draw a few hundred thousand outputs from M(D) and from M(D′), bin them, and take the largest log-ratio over bins both distributions actually reach. That estimate is noisy and biased upward, because you are taking a maximum over many noisy ratios — so it will exceed ε even when the mechanism is perfect. The fix is a control: run the identical estimator on two independent samples from the same distribution, where the true loss is exactly zero. Whatever it reports there is your noise floor, and the real measurement is only meaningful to that precision. This is how genuine privacy auditing works, and it is why audits produce lower bounds on ε, never certificates.
    
        
    A  = [M(D)  for _ in range(200_000)]
A2 = [M(D)  for _ in range(200_000)]      # SECOND sample from the SAME dist
B  = [M(D2) for _ in range(200_000)]

def max_log_ratio(x, y, bins, min_count):
    hx, hy = histogram(x, bins), histogram(y, bins)
    return max(abs(log((hx[i]/len(x)) / (hy[i]/len(y))))
               for i in range(bins) if hx[i] >= min_count and hy[i] >= min_count)

measured = max_log_ratio(A, B,  bins=32, min_count=1200)   # should be ~ eps
floor    = max_log_ratio(A, A2, bins=32, min_count=1200)   # TRUE answer is 0

assert abs(measured - eps) <= 3*floor + 0.05    # agreement within the instrument
# an audit gives a LOWER bound on eps. it can find a bug; it cannot certify.

    δ, and the Gaussian mechanism
    
        
    Gaussian noise cannot give pure ε-DP: its log-density is quadratic, so the log-ratio grows without bound in the tail and no finite ε covers every output. δ is the price of admission — the probability that the guarantee simply does not apply. With σ = Δf√(2ln(1.25/δ))/ε the loss is exactly Normal, so the tail probability has a closed form you can check directly, which this page does. Two warnings. That classical bound requires ε ≤ 1 and genuinely fails outside it — the verification suite asserts the failure at ε = 8 to prove the condition is load-bearing. And δ must be far below 1/n: at δ = 1/n, a “mechanism” that publishes one uniformly random person's entire record in the clear satisfies the definition.
    
        
    sigma = delta_f * sqrt(2 * log(1.25 / delta)) / eps      # requires eps <= 1

# under D the privacy loss is EXACTLY Normal, so the tail is closed form:
#   L ~ Normal( delta_f^2 / (2 sigma^2),  (delta_f/sigma)^2 )
def loss_tail(delta_f, eps, delta):
    s = sigma(delta_f, eps, delta)
    return normal_sf(eps - delta_f**2/(2*s*s), scale=delta_f/s)

assert loss_tail(1, eps=1.0, delta=1e-5) <= 1e-5        # holds
assert loss_tail(1, eps=8.0, delta=1e-5) >  1e-5        # BREAKS. eps<=1 matters.
# rule of thumb: delta << 1/n. at delta = 1/n, "publish one random row" is legal.

    The budget, and an accountant that spends it
    
        
    Privacy composes. Two ε-DP answers to the same question can be averaged, so the pair is 2ε-DP — sequential composition, and it is why a DP database contains a finite number of questions rather than a rate limit. Advanced composition does better for many queries by allowing a small failure probability, turning kε into roughly √(2k ln(1/δ′))ε + kε(e^ε−1) — note it is worse than the naive bound for small k, so an accountant that always uses it is leaving privacy on the floor. Both are conservative: the measured total loss on this page sits well below either, because the bound is a worst case over outputs while a real run sees typical ones. Modern accountants (Rényi-DP, zCDP, the moments accountant) close most of that gap, which is exactly why DP-SGD became practical.
    
        
    basic    = k * eps
advanced = sqrt(2*k*log(1/delta_prime))*eps + k*eps*(exp(eps) - 1)

# advanced is WORSE than basic for small k -- use min(basic, advanced)
budget = min(basic, advanced)

# parallel composition is the free lunch: queries over DISJOINT subsets of
# people cost max(eps_i), not sum(eps_i). every histogram exploits this.

# and once spent, it is spent. the honest options are:
#   - stop answering
#   - cache the noisy answer and return the SAME one forever
#   - never: "just re-run it, the noise is fresh"   <-- this is the leak

    Post-processing immunity — the property that makes DP usable
    
        
    Any function of a differentially private output is differentially private, with the same ε. No exceptions, no conditions, and the proof is immediate: post-processing cannot manufacture a distinction between two distributions that were already indistinguishable. This is why DP scales to real systems. Round the noisy count, clip it to be non-negative, feed it into a dashboard, train a model on it, hand it to an adversary with a supercomputer and every auxiliary dataset in existence — the guarantee is unchanged. Contrast that with k-anonymity, where merging two k-anonymous releases can produce a re-identifiable one. The one rule: post-process the output, never re-touch the raw data. Reading the true value again to “sanity-check” the noisy one spends budget you did not account for.
    
        
    # all of these are STILL eps-DP, for free:
noisy   = dp_count(D, pred, eps)
clean   = max(0, round(noisy))               # counts cannot be negative
report  = render_dashboard(clean)
model   = train(dp_release)                  # even this

# the proof, in one sentence: if no test can distinguish M(D) from M(D'),
# no function of them can either.  f(M(D)) and f(M(D')) inherit the bound.

# the one way to break it:
if abs(noisy - true_count(D)) > 100:         # <-- touched the raw data.
    noisy = dp_count(D, pred, eps)           #     budget spent, guarantee void.

    DP-SGD, and the ε values that actually shipped
    
        
    Training a model privately is the same recipe applied to gradients: clip each example's gradient to a fixed norm (that clip is the sensitivity), add Gaussian noise to the batch sum, and track the budget with an accountant. Per-example clipping is the expensive part — a normal backward pass only ever materialises the batch mean — and the accuracy cost is real, falling hardest on under-represented groups, which is a fairness problem the ε number does not show you. As for what the number means in practice: the 2020 US Census used ε ≈ 19.61 for the redistricting file, Apple has reported per-day budgets in the range 2–16 per feature, and academic work usually wants ε ≤ 1. Those are not comparable, because ε is only defined relative to a unit of privacy (one person? one record? one device-day?) and a neighbouring relation. Always ask what ε is per. A small ε on a badly chosen unit protects nothing.
    
        
    for batch in loader:
    g = [per_example_grad(x, y) for x, y in batch]        # the expensive part
    g = [gi * min(1, C / norm(gi)) for gi in g]           # clip  => sensitivity C
    noisy = (sum(g) + normal(0, sigma * C, shape)) / len(batch)
    params -= lr * noisy
    accountant.step(sigma, sample_rate)                   # RDP / moments

eps, delta = accountant.get_privacy_spent()
