AIFromZero · Day 62

🔬 Mechanistic interpretability — every weight of a language model is sitting on a disk you can read, and nobody can tell you why it produced the token it produced. Saliency and attribution methods (Day 60 in the DL track was Grad-CAM) answer “where did it look”; mechanistic interpretability asks the harder question — what algorithm is it running, and can I predict its behaviour on an input I have not shown you yet? This page tests that claim end to end on a model it trains live in your browser: a real attention-only transformer — token and positional embeddings, 2 layers, 2 heads, d_model = 16, hand-written forward and backward pass, Adam, no libraries — on a task whose correct algorithm is known before training starts: a block of tokens appears twice at a random offset, and after the second copy the model must continue it. The only rule that works is find the earlier copy of my own token, look at the token after it, copy that — the induction circuit Olsson et al. found in real models in 2022, and it provably needs two layers, so the page trains a one-layer control alongside and reports both. Then it takes the trained model apart. The central object is the residual stream: every component reads a normalised copy of it and writes back additively, nothing is overwritten, so a logit is an exact sum of one number per component — direct logit attribution is an identity, not an approximation, and this page checks it to 1.1e-15. On top of that, live: attention patterns showing the induction head fire and the previous-token head that feeds it, the K-composition linking them, ablation in all three flavours, activation patching where patching everything reproduces the clean run exactly, the logit lens, the QK and OV circuits in token space, and — because more features than neurons means features share directions — a toy superposition model and a real sparse autoencoder trained on this model’s own activations. Everything is computed here, now, from random initialisation No libraries, 740 assertions verified in Node against from-scratch reference implementations, bit-identical ablation controls and central finite differences, plus a 15,659-config sweep of every slider range.

First we train a transformer. Then we take it apart and find the algorithm inside.

No pre-trained weights, no stored results. The model below starts from random numbers when this page loads, trains on an induction task in a few seconds, and every panel underneath is computed from those weights.

✅ A circuit claim has to make predictions. The story this page tells — layer 0 builds a previous-token head, layer 1 uses it as a key to find where the answer lives, and the OV circuit copies it — is not asserted. It is turned into four falsifiable tests: a one-layer control that should fail and is measured failing, an attribution identity that must sum exactly, an ablation that must destroy accuracy, and a patch that must restore it.

⚠️ Circuit formation is a lottery, and the page does not hide it. Drag the seed. At the default budget the Node suite gets the circuit on 8 of 8 seeds (mean 99.3% against a one-layer mean of 24.4%) — but pull steps or batch down and that reliability collapses: hold everything else fixed and drop the batch from 24 to 16 and the same budget converges on only 3 seeds in 8. 2 · The residual stream is a sum — so attribution is exact arithmetic, not a heuristic

Every component in this network reads a normalised copy of the residual stream and adds its output back. Nothing overwrites anything. So the stream at the last layer is literally embed + pos + Σ head outputs, and because the final LayerNorm scale is a single number fixed by the forward pass, the unembedding is linear in that sum. Therefore each component contributes an exactly-defined number of logits to every token.

⚠️ The honest caveat about LayerNorm. This is exact because the final LayerNorm's scale is frozen at the value the real forward pass produced — the standard move, and the one TransformerLens makes when it folds LayerNorm. Freezing it is fair for attributing this run, because the scale genuinely was that number. It is not fair for asking “what would this logit be if the component were gone”, because removing a component changes the scale too. That question needs an intervention, which is exactly why panels 4 and 5 exist.
3 · Find the induction head — and the previous-token head that makes it possible

Two scores, both measured over the test set. Previous-token score is how much of position i's attention lands on i−1. Induction score is how much of a repeated token's attention lands on the position immediately after the earlier copy of itself — the signature.

4 · Ablation — break one component and measure what breaks

Attribution says a component contributed. Ablation asks whether it was necessary: delete its write to the residual stream and re-run. The three modes are not interchangeable and the table shows them disagreeing.

ablation

⚠️ Ablation is not a necessity proof. Three failure modes, all real, all in published work. A network can be redundant: two heads that both do the job each ablate to almost no effect and you conclude neither matters — the fix is to ablate them together, and the combinatorics are why nobody does that exhaustively. Zero-ablation can break the model for reasons unrelated to the circuit, because the stream is off-distribution and the LayerNorm scale shifts underneath everything. And a component can be load-bearing without being part of the story.

6 · The logit lens — unembed early and watch the answer arrive

Nothing forces you to apply the unembedding only at the end. Apply it to the residual stream after the embeddings, then after layer 0, then after layer 1, and you get a prediction at each depth.

probability of the correct token, by depth

—
⚠️ The logit lens is a convenience, not a theory. It assumes intermediate layers already write in the output basis — roughly true in this attention-only model with a shared unembedding, considerably less true in a deep production model where later layers rotate the basis and the lens goes blurry or confidently wrong. That failure is what motivated the tuned lens, which learns a per-layer affine map before unembedding.
7 · QK and OV — where to look, and what to move, as two separate matrices

The single most useful structural fact about an attention head: it factorises. WQWKT decides where to look and never touches the content that gets moved; WVWO decides what to move and never touches where it comes from.

positional QK of the previous-token head
WPWQWKTWPT — query position against key position. A previous-token head is a bright band one step below the diagonal.
K-composition into the induction head
(WEWQ1)(WEWV0WO0WK1)T — query token against “the position whose previous token was that token”. A diagonal here is the induction circuit.
OV of the induction head
WEWVWOWU — if I attend to token s, which logit goes up? A copying head is a positive diagonal.

⚠️ Why one layer cannot do this, stated precisely. In one layer the key at position j is a function of the token at j and the position j, and nothing else. The induction rule needs a key that says “the token before me was X” — information the key does not have. It must be written into position j by an earlier head and then read out of the residual stream by the later head's WK. That is K-composition, it requires depth, and the one-layer control is what happens when you take it away.
8 · Superposition, and the sparse autoencoder that tries to undo it

Everything above worked because heads are a natural unit. Neurons and directions are not. A model with n dimensions represents far more than n things, because real features are sparse — most are off most of the time — and a model would rather squeeze many features into overlapping directions and eat a little interference than keep only n of them.

⚠️ Read the SAE numbers with the scepticism the field now has. “Purity” here is scored against a label this toy setting happens to possess — the token each activation was produced to predict — and a real SAE has no ground truth at all, which is precisely the problem. Dead features waste capacity in every real run. And feature splitting is unresolved: widen the dictionary and one feature becomes five, with no principled answer to which width is right.
Four things people mean by “interpretability”, and what each one can actually support
Saliency / attribution
Gradients, Grad-CAM, integrated gradients, attention weights read as explanations. Cheap, and answers where did it look. Famously fails sanity checks — some saliency maps barely change when the model's weights are randomised.
Probing
Train a classifier on hidden states to see whether information is present. Answers “is it there”, never “is it used” — a probe can read a feature the model ignores.
Causal / circuits
Ablation, patching, path patching, causal scrubbing. Answers is it used, and for what. Expensive, and the honest ones report a fraction of behaviour explained.
Dictionary learning
SAEs and transcoders: find a basis in which activations are sparse, then interpret it. The best answer to superposition, with no ground truth to check it against.

Interpretability tooling fails silently: a broken attribution still produces a plausible bar chart, and a broken patch still produces a plausible heat-map.

🔨 Build it yourself

    
A transformer small enough to reverse-engineer is about 200 lines, and every interpretability tool on top of it is another ten to thirty.

    
    

      
  1. 
        
    1
    Build a model small enough to be understood — and drop the MLPs
    
        
    The first decision is architectural, not analytical. An attention-only transformer — embeddings, attention heads, unembedding, no MLP blocks — is the object Elhage et al. chose for the same reason: without MLPs the network's end-to-end function expands into a sum over paths, each of which is a product of matrices you can write down. Add MLPs and the sum stops being a sum.
    
        
    class TinyTransformer:                  # attention-only, on purpose
    W_E: [vocab, d_model]               # token embeddings
    W_P: [n_ctx, d_model]               # LEARNED positional embeddings
    layers: [ {W_Q, W_K, W_V: [head, d_head, d_model],
               W_O: [head, d_head, d_model]} ] * n_layers
    W_U: [d_model, vocab]               # unembedding

# no MLP, no attention bias, no learnable LayerNorm gain.

    2
    Pick a task whose correct algorithm you already know — and compute the controls
    
        
    Interpretability on a model trained on natural text has no ground truth: you find a story and cannot check it. So train on a formal task instead. Here: distinct random tokens with one block repeated at a random offset, predict the continuation. The only rule that works is find the earlier copy of my token, take the token after it.
    
        
    def make_seq(rng, V, T, K):
    toks = rng.permutation(V)[:T]              # all distinct
    b    = T - K                               # SECOND copy pinned to the end
    a    = rng.randint(0, T - 2*K + 1)         # FIRST copy moves
    toks[b:b+K] = toks[a:a+K]
    targets = [(b+i, toks[a+i+1]) for i in range(K-1)]
    return toks, targets

# WHY the second copy is pinned and the first one moves:
# if both move, the query's own position leaks how far back the answer is,
# and a ONE-LAYER model scores 42% off that leak instead of the 14% ceiling.
# this cost two rewrites to find. always attack your own task first.

def best_offset_baseline(data):            # what a positional rule can do
    return mean(max over d of  toks[pos - d] == y,  chosen per position)

    The forward pass, written so the residual stream stays a sum
    
        
    This is the single most important implementation detail on the page. Every component reads a normalised copy of the residual stream and adds its output back; nothing is ever overwritten.
    
        
    resid = W_E[toks] + W_P[:T]              # component 0
comp  = [resid.copy()]

for l in layers:
    n = layernorm(resid)                 # heads all read the SAME stream
    for h in heads:
        q, k, v = n @ W_Q[h], n @ W_K[h], n @ W_V[h]
        A   = softmax(mask(q @ k.T / sqrt(d_head)))     # causal
        out = (A @ v) @ W_O[h]
        comp.append(out)
        resid += out                     # ADDITIVE. never overwritten.

logits = layernorm(resid) @ W_U

    The backward pass by hand — and check it at initialisation, not at convergence
    
        
    Writing the backward pass yourself is the point: you cannot claim to have reverse-engineered a model you needed a framework to train. The softmax Jacobian is the only fiddly part, and it collapses to one line. Then gradient-check against central finite differences — with one rule that costs people hours. Run the check on freshly initialised weights.
    
        
    # softmax backward, for one row:
#   dS[j] = A[j] * (dA[j] - sum_k A[k]*dA[k])
# layernorm backward, no learnable params:
#   dx = (dy - mean(dy) - y*mean(dy*y)) / sigma

def grad_check(model, data, eps=1e-6):
    g = backward(model, forward(model, data))
    for name, W in model.tensors():                 # EVERY tensor
        for i in sample(range(W.size), 12):
            W[i] += eps; lp = loss(model, data)
            W[i] -= 2*eps; lm = loss(model, data)
            W[i] += eps
            fd = (lp - lm) / (2*eps)
            assert rel_err(fd, g[name][i]) < 1e-6

    Direct logit attribution — and the identity that proves it is not a heuristic
    
        
    Because the stream is a sum and the final LayerNorm scale is one frozen number, the logit for a token is an exact sum of one contribution per component. That distinguishes it sharply from gradient-based attribution, which is a first-order approximation to a nonlinear thing.
    
        
    def direct_logit_attribution(model, fw, token, pos):
    sigma = fw.final_ln_scale[pos]                  # FROZEN, from this run
    return [ ((c[pos] - c[pos].mean()) / sigma) @ model.W_U[:, token]
             for c in fw.components ]               # embed, then every head

parts = direct_logit_attribution(model, fw, tok, pos)
assert abs(sum(parts) - independent_forward(model, toks)[pos][tok]) < 1e-12

    Ablation, three ways — and a control that is bit-identical or wrong
    
        
    Implement ablation as an override on a component's write, and you get all three flavours from one code path plus patching for free. Then test the code path itself: zero-ablating a head must produce bit-identical logits to a forward pass in which that head was never computed. Not close — identical. If it is merely close, your override is landing somewhere it should not.

    Activation patching, and the two identities that keep it honest
    
        
    Run a clean prompt, run a corrupted prompt whose answer differs by one token, then splice a single clean activation into the corrupted run and measure how much of the logit difference returns. Normalise so 0 means “changed nothing” and 1 means “restored the clean behaviour”.
    
        
    metric = lambda fw: fw.logits[pos, clean_answer] - fw.logits[pos, corrupt_answer]

lo, hi = metric(run(corrupt)), metric(run(clean))
score  = lambda fw: (metric(fw) - lo) / (hi - lo)      # 0 = nothing, 1 = all

grid = [[ score(run(corrupt, patch={(comp, p): clean.components[comp][p]}))
          for p in positions ] for comp in components ]

assert run(corrupt, patch=EVERYTHING).logits == run(clean).logits    # exact
assert run(corrupt, patch={}).logits         == run(corrupt).logits  # exact

    QK, OV, and the K-composition that makes an induction head possible
    
        
    A head is two independent low-rank maps: WQWKT chooses where to look and WVWO chooses what to move. Sandwich each between embeddings and both become matrices in token space that you can simply look at. The induction head's key, though, is not built from the token at that position — it is built from what a layer-0 head wrote there.
    
        
    OV      = W_E @ W_V @ W_O @ W_U            # [V,V]  copying = positive diagonal
QK      = W_E @ W_Q @ W_K.T @ W_E.T        # [V,V]  token -> token
QK_pos  = W_P @ W_Q @ W_K.T @ W_P.T        # [T,T]  prev-token head = subdiagonal

# K-COMPOSITION: the key comes from what layer 0 WROTE, not from the token
K_comp  = (W_E @ W_Q1) @ (W_E @ W_V0 @ W_O0 @ W_K1).T      # [V,V]

# read it as: "query token t, against the position whose PREVIOUS token

    Superposition, and a sparse autoencoder trained on the model's own activations
    
        
    Heads are a natural unit; neurons are not. A model with n dimensions represents many more than n features, because features are sparse and it is worth eating some interference to keep them all. Anthropic's toy model reproduces this in about forty lines: on dense data it keeps n features, on sparse data it keeps far more.
    
        
    # superposition, in one model:
x_hat = relu(W.T @ (W @ x) + b)        # W: [n_features, n_dims], n_dims < n_features
loss  = sum(importance * (x - x_hat)**2)
# sparse x  =>  MORE than n_dims features get a direction. that is the result.

# the sparse autoencoder:
h     = relu(W_enc @ (x - b_dec) + b_enc)      # overcomplete: len(h) >> len(x)
x_hat = W_dec @ h + b_dec
loss  = ||x - x_hat||^2 + lam * sum(h)         # L1 => sparse code
W_dec = normalise_columns(W_dec)               # or L1 is gamed for free
