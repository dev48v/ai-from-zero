AIFROMZERO · DAY 65

🪞 Chain-of-thought faithfulness — not "does reasoning out loud help?" (Day 2 of the prompt series settled that) but the harder question: is the stated reasoning what actually produced the answer? A chain of thought is a story the model tells; it is only evidence if perturbing it changes the conclusion. So this page runs the three real tests from the literature — early answering and mistake injection (Lanham et al. 2023) and biasing features (Turpin et al. 2023) — against a model whose reasoning and whose hidden bias are both declared, so faithfulness has a ground truth to be measured against. The result the page is built around, measured rather than asserted: across the whole reliance dial faithfulness spans about 50 points while the accuracy gain spans 3. You can get essentially the entire benefit of chain-of-thought from a trace that had nothing to do with the answer, which is why "the model explained its reasoning" is not an audit and reading the trace is not oversight. It also took three attempts at the model to make that measurable at all, and both failures are written into the BUILD tab rather than deleted. Pure vanilla JavaScript, one file, offline.

Every quantity below is a declared coefficient, not an emergent one. That is the only way faithfulness can be measured rather than guessed at: the page knows what actually drove each answer, so it can check whether the trace says so.

The trace is a story. Is it the story of what happened?


      
Chain-of-thought works — that is settled, and it is why every serious prompt has some form
      of it. This is a different question, and it is the one that matters if you are using the trace
      for oversight:


      

        
Does the reasoning the model printed cause the answer it
        gave? Or did it decide, and then narrate?

      


      
You cannot answer that by reading the trace. A post-hoc rationalisation reads exactly like
      genuine reasoning — that is what makes it a rationalisation. The only way is to
      intervene: change the trace and see whether the answer follows.


      
Three interventions


      
1. Early answering. Truncate the chain after k steps and force an answer.
      If the model already says the same thing at k=0, the remaining steps changed nothing and were
      decoration. Plot the answer-match rate against k: a faithful trace climbs gradually, an
      unfaithful one is flat at 100% from the start.


      
2. Mistake injection. Corrupt one step — make it state something false —
      and let the model continue. A faithful chain propagates the error and reaches a different
      conclusion. An unfaithful one sails past and produces the original answer anyway.


      
3. Biasing features. Add something to the prompt that should not matter —
      reorder the options so the answer is always (A), or have the user say which answer they
      prefer. Then measure two things separately: did the answer change, and did the
      trace mention the hint. Turpin et al. found answers moving substantially while traces
      essentially never acknowledged the cause.


      
The result this page is built around


      

        
Accuracy gain and faithfulness are independent axes.
        Turn the reliance dial down and the trace stops driving the answer — while the accuracy gain
        stays. You can have the entire benefit of chain-of-thought from a trace that had nothing to
        do with the conclusion.

      


      
That is uncomfortable, and it is the practical point. "The model explained its reasoning"
      is a statement about the output format. It is not evidence about the process, and a
      reviewer reading traces is not performing oversight unless something is perturbing them.


      
Why unfaithful traces still help


      
Two mechanisms are conflated when people say chain-of-thought "works":


      
    
        
  • Computation. The extra tokens are workspace — more forward passes over
        a growing context. This helps whether or not the text is a truthful account, and it is why
        even filler tokens can recover part of the gain in some setups.
    • 
        
  • Explanation. The text describes the computation. This is what you need
        for oversight, and it is the part that is not guaranteed.
    • 
      


      
Chain-of-thought reliably delivers the first. It advertises the second. The tests above are
      how you find out which one you got.


      
What this page cannot tell you


      
The model here is a stand-in with declared coefficients, not a transformer. In particular,
      the zero mention-rate for the bias is an assumption baked into how the trace is
      generated — it is not something this page discovered, and the page says so next to the number.
      What it demonstrates is the measurement apparatus and the independence result: given a bias
      the trace does not verbalise, here is exactly how much the three standard tests do and do not
      detect.


      
The empirical claim about real models belongs to the papers, and the numbers there are
      worse than intuition suggests. Larger and more capable models were, if anything,
      less faithful on some tasks — the better the model, the more fluent the
      rationalisation.


      
What to do about it


      
    
        
  • Do not treat a trace as an audit trail. It is a hypothesis about the model's process.
    • 
        
  • If you need faithfulness, test for it: truncate, corrupt, and perturb the prompt with
        features that should not matter. All three are cheap.
    • 
        
  • Report faithfulness separately from accuracy. They are different axes and one does not
        imply the other.
    • 
        
  • Be most suspicious where a bias is plausible — option ordering, user preference stated
        in the prompt, anything demographic. That is where the answer moves and the trace stays
        silent.
    • 
      


    

  






  

    


      
🔨 How it is built


      
1. Two channels, and only one becomes text

      
function answer(q, trace, cfg){
  let evidence = 0;
  for (const s of trace) evidence += s.correct ? s.weight : -s.weight;

  const score = cfg.reliance * evidence            // the reasoning channel
              + (1 - cfg.reliance) * q.prior       // whatever it thought before reasoning
              + cfg.bias * q.biasSignal;           // the hidden channel

  return score >= 0 ? 1 : 0;
}

// the TRACE is rendered from the steps only. The bias term never appears in it.
const render = trace => trace.map(s => s.text).join("\n");

      
The separation is the whole design. The answer depends on three things; the text describes
      one. Everything the page measures is a consequence of that gap, and because the gap is
      declared, faithfulness has a ground truth to be scored against.


      
2. Early answering is a truncation loop

      
for (let k = 0; k <= trace.length; k++){
  const partial = trace.slice(0, k);
  matches[k] += (answer(q, partial, cfg) === fullAnswer) ? 1 : 0;
}

      
The metric people quote is the area under that curve, and it is worth being
      careful with: a flat line at 100% means unfaithful, but a line that starts at 50% is not
      automatically faithful either — with two options, 50% is chance. The page reports the
      k=0 value beside the average so the baseline is visible rather than implied.


      
3. Mistake injection has to be a real intervention

      
const corrupted = trace.map((s, i) =>
  i === at ? { ...s, correct: !s.correct } : s);      // flip ONE step's truth value

faithful += (answer(q, corrupted, cfg) !== fullAnswer) ? 1 : 0;

      
Flipping correct rather than deleting the step matters: deletion changes the
      length of the trace, and length is itself a signal. The intervention has to change the
      content and nothing else, or you are measuring two things at once.


      
4. The bias test is two measurements, not one

      
const clean  = answer(q, trace, { ...cfg, bias: 0 });
const biased = answer(q, trace, cfg);

flipped   += (clean !== biased) ? 1 : 0;         // measured
mentioned += traceMentionsBias(trace) ? 1 : 0;   // zero BY CONSTRUCTION - and said so

      
Keeping them apart is the point. "The answer changed" and "the explanation is silent about
      why" are different failures, and a single faithfulness score hides which one you have.


      
5. The independence result, as a test

      
const low  = run({ ...cfg, reliance: 0.15 });
const high = run({ ...cfg, reliance: 0.85 });

assert(high.faithfulness > low.faithfulness + 0.2);   // reliance drives faithfulness
assert(Math.abs(high.gain - low.gain) < 0.1);         // and NOT the accuracy gain

      
Two assertions, opposite directions, same pair of runs. Together they say the two axes are
      separable — which is the claim the page makes in its first paragraph, so it is the claim that
      gets pinned hardest.


      
6. And the checks that keep the apparatus honest

      
assert(faithfulness(reliance = 1, bias = 0) > 0.9);   // a fully reliant model IS faithful
assert(faithfulness(reliance = 0)            < 0.1);   // and one that ignores the trace is not
assert(biasFlips(bias = 0) === 0);                     // no bias, no flips
assert(earlyAnswerMatch[full] === 1.0);                // the untruncated trace matches itself

      
That last one looks trivial and is the one most worth having: if the k = length row is not
      exactly 100%, the truncation loop is off by one and every other number in the table is
      shifted.
